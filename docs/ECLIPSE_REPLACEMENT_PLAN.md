# ECLIPSE 替换计划书 —— 以 simulator.html 为基线重构暗夜主题

> 依据：`theme-styles/eclipse/simulator.html`（7314 行，36 屏全功能演示）
> 原则：**布局框架全局共享（三皮肤同一套）；配色与材质按皮肤分发，classic / blueGlass 的色值不动；nocturne（暗夜）整体升级为 eclipse。此后主题演变只换配色令牌，框架冻结。**

## 0. 先纠正一个预期：这不是"替换 UI"，是"暗夜 V2 校准"

读完模拟器源码，结论明确：**eclipse 不是一套新 UI，它就是现有暗夜皮肤的全功能演示版**。证据：

- 画布注释直接引用源码文件与换算：`源码 launcher_dialog 760×650，×5/6 = 633×541`、
  `对应源码 dock_music_progress_background.dart：shader 满铺整个音乐胶囊`、
  `诊断日志（diagnostics_settings.dart 真值）`、`对应源码 storage_cleaner_panel.dart`。
- 视觉语言与已实现的 nocturne 完全同源：`#050607` 画布、一卡一色底部光晕（六个卡色
  `#3BE2C0 / #4E8CF8 / #8E6CFF / #FF5FA8 / #FFB057 / #6FD3FF` 一字不差）、25px 卡圆角、
  卡底 66px 压暗带、`k-num` 细体大数字、顶栏 53.33px、floating dock。
- 流体烟雾 shader 的 JS 注释写明"1:1 移植自源码"，参数（seed 2.54、stiffness 26 /
  damping 9.5）与本地未提交的 `fluid_progress.frag` 同一套。

所以工作量形态是：**令牌校准 + 局部结构升级 + 少量新屏**，不是重写。上次方案书
（`NOCTURNE_REPLACEMENT_PLAN.md`）的口径继续有效，本次把范围扩到全部 36 屏。

## 1. 现行主题引擎结构（被替换的对象）

```
Appearance (model/appearance.dart)
  └─ themeStyles = ['classic', 'blueGlass', 'nocturne']   ← 唯一注册表
SurfaceStyle (theme/launcher_theme.dart:54)                 ← 18 个语义令牌分发器
  ├─ .from()           按 themeStyle 字符串三分支
  ├─ _nocturne()       暗夜工厂（本次替换的核心）
  └─ Nocturne          六卡色 + _glow 18 类型光晕查表
消费侧：132 处 SurfaceStyle.of() / 48 文件；nocturne 行为分支散在
glass_surface / scene_background / desktop_drag / editable_card / dock_music_progress_background
```

**"UI 界面全部替换"在代码里的真实含义**：widget 树就是框架，三套皮肤共用同一棵树。
树不能整体换——换了 classic/blueGlass 就死了。能换的是三样：
① 令牌值（`_nocturne` 工厂 + 调色板）；② eclipse 设计里变化的结构（按皮肤位门控）；
③ 少量新屏。这正是模拟器自己演示的架构：同一套 DOM，`data-theme` 切材质、
`--acc` 切配色。

## 3. 目标架构：两轴正交（布局无条件 / 材质按皮肤分发）

### 3.1 关键事实：布局已经是三皮肤共用的，而且数值与 sim 完全一致

`desktop.dart` 与 `card_content.dart` 里**零处皮肤判断**，网格、卡片坐标、页结构
三皮肤共用一棵树。实测单位也逐项对上（代码 `Design.px(v) = v × 5/6`，sim 是 1600 值）：

| 结构 | 代码 | 换算 | sim | 是否一致 |
|---|---|---|---|---|
| 顶栏高 | `desktop.dart:53` `px(64)` | 53.33 | 53.33 | ✅ |
| 卡左/上边距 | `desktop.dart:227` `px(32)` | 26.67 | 26.67 | ✅ |
| dock 预留高 | `bottom_dock.dart:168` `px(96)` | 80 | 71.67+4.17×2=80 | ✅ |
| dock 按钮 | `bottom_dock.dart:382` `px(64)` | 53.33 | 53.33 | ✅ |

结论：**「玻璃和经典也要用新布局」不需要任何操作——它们本来就在用同一套布局**。
eclipse 相对现状的差异只有两类：**新增元素**（tick 角刻线、底栏歌词位、页点位置、
uni 菜单 V2 细节）和**材质参数**（渐变 stops / edge / 阴影 / 压暗带）。

因此全仓 1375 处 `Design.px` 不需要换基准。sim 的 1600 值直接 `Design.dz(v)`，
或 `Design.px(v × 1.2)`，两者等价，逐点换算即可。

### 3.2 架构改造：把混在一起的皮肤位拆成两轴

现状 `nocturne` 布尔位同时承担三件事，这是所有麻烦的根源：
① 材质（surface 渐变、阴影、无模糊、快照兜底）② 装饰（光晕、dock 色）
③ 布局暗示（底栏音乐块 flat、radius 用 dz）。改造后：

```
轴 A · 布局（framework，无条件，三皮肤共用）
  ├─ 网格 / 卡片坐标 / 页结构 / dock 几何 / 顶栏高
  ├─ 新增元素：tick 角刻线、页点居中、底栏歌词位、媒体胶囊结构
  └─ 禁止任何 if (skin) 分支；新元素一律走无条件路径

轴 B · 材质（SkinMaterial，每皮肤一张表）
  ├─ cardSurface(4 段 stops) / edge / shadow / 压暗带
  ├─ dockSurface / sheetSurface / mediaCapsule / 玻璃胶囊
  ├─ accent 组：accHi / accLo / accDeep / acc2
  ├─ 策略位：blurPolicy / glowPolicy / snapshotPolicy / controlStyle
  └─ 装饰位：cornerTick、technicalBracket（blueGlass 专属角框）
```

- `'nocturne'` ID 保留不改名（老配置无损、`git revert` 可回滚），显示名改「ECLIPSE · 日蚀」。
- 此后新增皮肤 = 新增一张 `SkinMaterial` 表 + 工厂分支，widget 一行不动。

### 3.3 三皮肤材质表要填的新色值（这是"保留原配色"的实际工作量）

新布局元素对每套皮肤都需要一个色值，缺一个就会出现"某皮肤下元素不可见/发灰"：

| 新元素 | classic（明/暗双态） | blueGlass（明/暗双态） | eclipse（仅暗） |
|---|---|---|---|
| tick 角刻线 | `edge` | `corner` | `rgba(ink,.10)` |
| 页点（on/off） | `text` / `disabled` | `accent` / `edge` | `ink .85` / `ink .22` |
| 底栏歌词位 | `muted` | `accent` | `acc @ .62` |
| 进度条渐变 | `accent` 单色 | `accent → acc2` | `mint → cyan` |
| 媒体胶囊面 | `soft`（浅底） | `dock` 渐变 | 深玻璃 + 紫光晕 |
| 空调胶囊面 | `soft` | `dock` | `rgba(ink,.043)` |
| 卡片压暗带 | 不用（浅底会脏） | 可选 `edge` 5% | 黑 34% |
| uni 菜单 tag | 隐藏 | 隐藏 | `acc @ .28` 描边 |

**唯一会真崩的组合**：sim 的媒体胶囊是硬编码深玻璃
（`rgba(25,26,32,.88)`）+ 薄荷流体，eclipse 专属光源。**classic 浅色模式下必须换
浅玻璃底并把流体关掉**，否则浅色底栏里挂一块黑砖。这是"共用布局"里唯一的
必填项，也是最容易漏的一项。

### 3.4 三主题匹配规则（本版的验收契约）

用户确认：**布局三皮肤共用，配色按各自原样。** 落到工程上是一条硬规则：

> 任何新增的视觉元素，必须在材质表里给 **classic 明 / classic 暗 / glass 明 /
> glass 暗 / eclipse 暗** 五档都留位置。classic 与 blueGlass 有明暗两态，
> eclipse 只有暗态。漏一档 = 该皮肤在某个明暗状态下元素消失或糊住。

按 §3.3 的 8 类新元素 + 设置页新增 6 类（左导航选中态、分类标题、分区块面、
滑动条、开关、空态提示）计算：**14 类元素 × 5 档 ≈ 70 个色值条目**。这就是
"3 个主题都要匹配"的真实成本，也是本版最容易翻车的地方——不是难，是数量多、
漏一个不容易发现（要专门切到那套皮肤那个明暗态才看得见）。

必须有的兜底机制：

1. `SkinMaterial` 里所有字段 `required`，无默认值 → 编译器强制填满，漏了直接编不过。
2. 新增一个 `three_skin_golden_test.dart`：三皮肤 × 明暗两态共 5 个状态，逐屏出图，
   与基线比对。这是唯一能自动发现"某皮肤某态下元素没了"的手段。
3. 设置页左导航选中态要重点看：classic 是**实心 accent 底**、blueGlass/eclipse 是
   低透明度描边底——`selectedText` 已经处理了这个差异，新增元素不要绕开它自己写色。

## 字体：走系统字体后的标定（2026-11-07）

**决定：不内置字体，跟随车机系统字体。** 依据是许可，而不是体积：

| 字体 | 免费商用 | 可嵌入 App | 可子集化 |
|---|---|---|---|
| HarmonyOS Sans SC | ✅ | ✅ | ❌ 协议第 2 条「不得做任何修改」 |
| MiSans（小米） | ✅ | ✅ | ⚠️ 不得改编/二次开发 |
| 思源黑体 / Noto Sans CJK | ✅（OFL 1.1） | ✅ | ✅ |
| 苹方 / 微软雅黑 | ❌ | ❌ | ❌ |

设计稿字体栈首选鸿蒙 Sans，但它禁止裁字，完整简中一个字重 10 MB 量级；
换 MiSans 又要重标所有字宽。所以本轮改为**跟随系统字体**。

### 实测度量（直接读 TTF/TTC 的 head + hhea + hmtx + cmap，em 归一）

| 字体 | 默认行高 | 汉字「中」 | 数字「0」 |
|---|---|---|---|
| 雅黑 Regular | 1.320 | 1.000 em | 0.586 em |
| 雅黑 Bold | 1.320 | 1.000 em | 0.617 em |
| 雅黑 Light | 1.330 | 1.000 em | 0.556 em |
| 等线 DengXian | 1.042 | 1.000 em | 0.527 em |
| Segoe UI | 1.330 | — | 0.539 em |
| Noto Sans CJK（车机常见） | ≈1.448 | 1.000 em | 0.500 em |
| Roboto（Android 拉丁默认） | ≈1.171 | — | 0.556 em |

### 三条结论

1. **字号不用改。** 汉字的 advance 在所有中文字体里都恰好是 1.000 em，
   换字体不会改变汉字宽度，所以不存在「字号要等比缩放」这回事。
   设计稿的 19（画布单位）在 1920 屏上就是 22.8 px，换了字体仍然是 22.8 px。
2. **行高必须钉死。** 默认行高在字体之间差 30%（Roboto 1.17 → Noto CJK 1.45）。
   正文用 `LauncherType.lineBody = 1.32`（雅黑实测值），说明段用 1.6，
   单行标签用 1.2。不钉死的话，同一份代码在不同车机上中文行距会明显不一样。
3. **数字宽度随字重变。** 雅黑 400→700 数字宽 0.586→0.617 em（+5.3%），
   且不同字体在 0.50~0.62 em 之间。时钟、车速、温度这类读数必须用
   `LauncherType.numeralStyle()`（等宽数字 + 单行行高），否则数值变化时串会抖。

### 落到代码

- 新增 `app/lib/theme/launcher_type.dart`：13 档字号阶梯（覆盖设计稿的 0.5 步长网格）、
  三档字重（400/500/700）、三种行高、等宽数字样式；`family = null` 显式声明跟随系统。
- `launcher_theme.dart` 的 `textTheme` 走 `LauncherType.family`，按钮行高改 `lineTight`。
- 设置页 12 处段落行高（1.5 / 1.6 / 1.66 / 1.7 / 1.75）统一到 `lineLoose`。
- 存量页面仍照设计稿原值写（像素对齐优先），新组件才从阶梯里挑。

### 一个已知的预览/车机差异

`FontWeight.w300` 在设计稿里大量使用（23 处）。系统 CJK 字体一般只有
Regular 与 Bold，缺 500/300 时 Skia 会**回落到 400**（不会合成细体）。
所以：Windows 预览里有雅黑 Light，看起来是细的；车机上等于 Regular。
`LauncherType.harmonize()` 把 200~300 显式收敛到 400，让预览与车机一致。
代价是设计稿那层「细字重」的精致感在车机上本来就复现不了。

**标题字重：决定维持 w500，不改（2026-11-08 用户定）**。理由：
① 设计稿本来就是 w500，提到 w600 是计划外的提议，不是稿子要求；
② `harmonize()` 已经把 200~300 收到 400，预览与车机的差只剩「车机有没有 500
   这一档」——有 500 时标题比正文重一档，没 500 时回落 400 与正文同重，都还在
   可接受范围；提到 600 会落到 Bold，比稿子厚一整档，反而更偏；
③ 全站标题粗细是一个很显眼的变化，换来的只是「车机上层次稍明显」，不值得。

## 设置页三皮肤体检（2026-11-08）

起点是用户一句「暗夜跟玻璃和经典里面每个区域的高度、按钮大小好像不一致」。
外观页确认有差异并已修（下方第 1 条），随后把十屏全部过了一遍。

### 体检方法

不做人工看三十张图。三层量化：

1. **带 key 控件几何**：`ChoiceButton / DesignSwitch / SettingBlock /
   SettingRow` 的 `局部坐标 + 尺寸`，三皮肤逐项比。覆盖 175 个控件。
2. **文本矩形指纹**：所有 `RichText` 的 `(top, width, height)` 排序后比。
   不带 key 的块内文字、段落换行都在这里，比第 1 层覆盖更广。
3. **滚动量**：每页所有 `Scrollable` 的 `maxScrollExtent`（带位置排序）。
   某皮肤内容变长会在这里现形。

一开始还试过截图边缘检测（长横线判据：某行 55% 以上像素在 y 方向有突变），
它能抓块边框，但在浅色皮肤上白 7% 的描边几乎不可见，`cluster` 页直接失效，
只适合当辅助证据。

### 结论

| 页 | 结果 |
|---|---|
| appearance | **有差异**（主题风格 42/47、主题配色 76/86 画布按皮肤分流）→ 已统一为暗夜值 |
| 其余九页 | 三皮肤控件几何、文本指纹、滚动量**逐项相同** |

appearance 里剩下的 3 处文本横向偏差是「同一页三皮肤各自选中不同的主题样式
按钮，勾图标让按钮内文字挪 10~12 px」，属选中态差异，不是布局问题——所以
第 2 层指纹只比纵向位置与宽高，不比横向。

### 落成回归

`test/three_skin_geometry_test.dart`：十页 × 三皮肤，逐个断言上面三层指纹。
用**结构指纹**代替计划书 §3.4 要求的 golden 图，理由写在该文件头：

## P4 配色系统（2026-11-08）

计划书 §4 P4 两条都做了，全部在 Dart 侧。

### 1. 自定义色相改按 HSL 算

`Appearance.accent(dark)` 里 `palette == 'custom'` 原先走
`Color.lerp(seed, white/black, .42)`。以正红 `#D42A2A` 为例实测：

| | RGB | HSL | HSV |
|---|---|---|---|
| 用户选的 | `#D42A2A` | h0 s.67 **l.50** | s.80 v.83 |
| 旧 lerp 白 .42 | `#E68383` | h0 s.66 **l.71** | **s.43** v.90 |
| 新 hsl(0,.68,.66) | `#E36D6D` | h0 s.68 **l.66** | s.52 v.89 |

偏差是「太亮 + 彩度掉一半」，屏幕上是一块浅粉，选正红的人看不出自己选了红。
现按 sim `hslTriple`（`simulator.html:7156`）算：暗底 `hsl(h,.68,.66)`、
浅底 `hsl(h,.78,.26)`，色相不动、明度对齐预设的 `dark` / `light` 两档。

顺带一个坑记一下：**HSL 的 saturation 在这里几乎不变（.67→.66）**，所以不能
拿它当判据；能看出问题的是明度与 HSV 彩度。

### 2. 色球按 board 09

`_PaletteDot`（新，`settings_screen.dart`）：

- 三段竖直渐变 `180deg, top, seed 55%, bottom`，三段用 board 09 的**字面值**
  （`AccentPreset.dotTop / dotBottom`，`seed` 正好是中间段）。之前是从 seed
  往白/黑 lerp，六颗球都偏灰；
- 补上 `.dot::before` 那层顶部高光（左右内缩 3、top 2、占 45% 高，白 32%→0）：
  没有它球面是平的，六颗球看着像六个纯色方块；
- 选中勾 16 → **20**（稿子就是 20）；`Icons.check_rounded` 对应稿子
  `stroke-linecap:round`；
- 「自定义」球从 `SweepGradient`（默认从正右起）改成 `GradientRotation(120°)`，
  对齐 CSS `conic-gradient(from 210deg)`；色标第三段是**活的**当前强调色
  （`customDotColors(s.accent)`），换色相时球面上能看见自己那一档。

球尺寸 38 / 圆角 13 / 卡片 `padding 6 0` / 名称 14 号，本来就与 `#f9 .pcol`
覆盖值一致，没动。

### 2b. 浅色态翻车：高光不能跟着 `--ink` 走

第一版 `_PaletteDot` 把高光层写成 `s.text.withValues(alpha:.32)`，直译稿子的
`rgba(var(--ink),.32)`——暗色皮肤下 `ink` 是白，看着没问题；**浅色皮肤下
`ink` 翻成深墨，那层「高光」就成了灰影**，六颗球全部呈现「上暗中亮」的双环，
用户一眼看出「浅色状态下显示不对」。

修法：高光恒用 `Colors.white`。球面是固定彩色，它的高光不会因为界面切成
浅色就变成阴影。顺带把球的投影在浅底上从黑 55% 收到 22%——`0 6px 14px
-6px rgba(0,0,0,.55)` 是给近黑画布配的，原样压在浅底上就是一圈黑晕。

这类问题**几何测试抓不到**（尺寸一个都没变），所以补了像素级用例
`test/palette_dot_highlight_test.dart`：整棵树包一层 `RepaintBoundary`，
`toImage()` 取像素，比较同一颗球「顶部高光带」与「球身中带」的平均亮度。

- 覆盖 blueGlass / classic 的明暗两态 + nocturne（暗夜恒暗，light 一轮等价跳过），共 5 条；
- 变异验证：把高光改回 `s.text`，浅色两条立刻失败（差值 3.2 / 2.9 < 阈值 6），
  深色两条仍通过——正好复现「只有浅色不对」这个现象。

同时给 `preview/main_preview.dart` 补了 `UNI_PREVIEW_MODE=light|dark`：以前
浅色态的截图只能靠系统主题碰运气，现在能钉死。

### 3. classic / blueGlass 的连带变化

`accent()` 是两套老皮肤共用的入口，所以自定义色在它们身上也一并从 lerp 变

## P9 卡片铺满：点开只剩这一张（稿子 f5，2026-11-13）

| 动画 | `_CardFocus`：**只做 Transform + Opacity**，卡片按整页尺寸只布局一次，逐帧只改合成层的位移与等比缩放，不 relayout、不重建子树——开销和一次 220ms 页面转场同级；系统关动画时直接跳终态。所以选了 B（从卡位长出来 + 反向收回）而不是 A |

| 退出 | 铺满层统一在右上角给一颗「收起」键（`card-focus-close`），任何卡片都有 |

### 实车回修五：暗夜 + 壁纸下卡片/按钮半透明、糊成一团黑

现象（用户实车截图）：暗夜主题选了壁纸后，按钮全变透明，卡片像一团黑；设置页里的
「叠加主题渐变」拨了没反应。

根因两条，都是「暗夜这套皮肤是围着近黑画布设计的」：

1. 卡片只给 5% 白（渐变的 `0x16→0x04`），按钮 6% 白，阴影是 `rgba(0,0,0,.9)` + 54 模糊。
   近黑画布上那层阴影看不见；换成照片后，阴影变成卡片底下一坨黑，卡片本体又把照片
   透上来 → 「透明 + 黑团」。
2. `_nocturneBackdrop` 在有壁纸时只画一层 60% 黑，**根本没读 `wallpaperOverlay`**，
   所以开关是死的；而且 60% 黑把照片吃得只剩灰影，选壁纸等于选了个黑底。

做法：

| 层 | 改动 |
|---|---|
| `SurfaceStyle` | 新增 `wallpaperBacked`（只在暗夜 + 非「主题渐变」壁纸时为真）。此时 `surface` 8%→90% 实底、`soft` 6%→70%、`strong`/`edge` 同步加深。没壁纸时**一个值都不变** |
| `GlassSurface._nocturne` | 有壁纸时卡片填充换成近黑**半透**渐变（`0xB4`→`0xC0`，约 72%，照片隐约透出、顶端留一点高光保住玻璃感；按用户决定**不加实时模糊**），阴影 `0xE6/54/-26` → `0x8C/34/-16`；底栏音乐胶囊 `0x1AB3D9D9` → `0xCC0B0D0E` |
| `SceneBackground._nocturneBackdrop` | 压暗 60% → 40%；`叠加主题渐变` 打开时在照片上叠主题色渐变（accent .22 → .04 → 底部 0x8C 黑），关掉就是纯照片 + 压暗 |

「叠加主题渐变」的语义（原版也是这个意思）：选了壁纸后，再叠一层**主题色渐变**，让照片
跟主题同调、并给卡片和文字留出对比度；关掉就是原照片。这个开关现在三套皮肤都生效了
（之前只有 classic / blueGlass 实现）。

回归：`test/nocturne_wallpaper_test.dart`（标记只对暗夜 + 壁纸为真、表层色够实、
开关真的改变背景）。渲染对照 `app/build/after_plain.png` / `after_overlay.png`。

### 实车回修二（2026-11-13 傍晚）：点音乐卡弹出的是旧弹层

现象：车上点音乐卡，出来的是 1040 宽的旧媒体弹层（另一套窗口，标题「网易云音乐 · 正在播放」），

两处成因，都是「桌面把自己的活交给了另一个窗口」：

1. **`showMusicPlayer` 先 `presentGlobalPanel('media')`**。车机上底栏服务常态在跑、可见、已授权，
   这一步**总是成立**，于是转去底栏的面板窗口画 `MediaPanel` —— 那就是旧弹层。调试模式下底栏
   没跑，这一步返回 false，才落到 `focusCard`，所以只有真机复现。
   现在：桌面这一侧直接 `focusMusicCard()`（卡片不在当前页会先翻过去），不再转交；只有**底栏

   才退回老的媒体面板。
2. **桌面被 `globalDock.expanded` 门控，却收不到它的更新**。`Desktop` 整块套在
   `TickerMode(enabled: expanded != true)` 里，而面板开合只走 `GlobalDockService` 自己的
   publish（只喂底栏/面板两个引擎），桌面要等下一次遥测才知道 `expanded` 变了 —— 于是关掉面板
   后桌面还停在「面板开着」：翻页不落位、卡片动画全停。
   现在：`showPanel` / `dismissPanel` 都调 `MainActivity.requestPublish()`，桌面立刻拿到新的
   `expanded`。

### 桌面翻页：去掉空白尾页 + 首尾环回（2026-11-14 晚）

**① 空白尾页只在编辑态存在。**

第三页一直是「添加一张卡片」那颗按钮的临时尾页（`_gridsFor` 里 `pageCount` 之后多挂的
一格）。用户 2026-11-14 要求普通浏览时不显示它 —— 编辑态仍能加卡（编辑条「添加卡片」
按钮、满页时 `add()` 自动开新页）。

- `desktop.dart`：临时尾页的条件从 `pageCount < 20` 改成 `editing && pageCount < 20`；
- 页点数量同步：`pageCount + (editing ? 1 : 0)`（原来无条件 +1）；
- `controller.switchPage`：非编辑态上限改成 `pageCount - 1`，避免滑到不存在的页。

**② 向左滑到头 → 环回第一页（用「平移」效果）。**

位置层实现，不是复制页面：拖动越界时把**另一端那一页**用**虚拟序号**挂在当前页右边
（向前环回：`children.length`）或左边（向后环回：`-1`）一起参与平移，所以它跟着手指
**从右侧滑进来**，方向与手指一致；松手后位置推到虚拟终点（last+1 / -1），动画结束再
换算成真实页并通知控制器。

- 只走平移：环回期间忽略 depth / zoom（那两套是"翻页"语义，套在环回上方向会错乱）；
- 只在普通浏览生效：编辑态（留给边缘拖卡换页）、铺满一张卡、设置页、拖拽落位时 `wrap: false`；
- 双向：第一页继续向右滑 → 环回最后一页；
- 页点不跟着跑：指示条把位置夹在 `[0, pageCount-1]`。

**踩过的三个坑**（都写进注释了）：
1. 第一版做成「原地淡入」，实车观感是两页叠影 / 一闪，用户要求改成平移；
2. 虚拟序号的方向**不能比索引大小**：向前环回是 last → 0，索引更小，按大小判会把
   进来的那页挂到左边（越滑越黑）。判据是「目标 0 且起点最后一页」；
3. **三页桌面上手指一动就窜进来半屏**：位移公式按 `|to - from|` 归一化，
   环回时 to 用真实索引 0、from 用 last，三页时差 2 → 位移被砍一半（拖 10% 露 47%）。
   现在环回给一个**相邻的虚拟 to**（`last+1` / `-1`），并关掉普通翻页那套
   「未覆盖裁剪」（环回两页都可能满宽可见，裁了会像被切一块）。
   两页桌面时差本来就等于 1，所以这个 bug 只有三页才看得见。

回归：`test/desktop_page_wrap_test.dart` 五条 —— 普通态没有 `desktop-grid-2`（编辑态才有）、
末页向左环回第一页（越界按平移跟手：position 1.6，收尾 150ms）、首页向右环回最后一页、
`wrap:false` 时到头只回弹、以及**按像素**断言平移（左半还是当前页、右半已经是第一页、
落定后整屏是新页）。`launcher_widget_test` 里那条「总是有一张临时尾页」改成编辑态才有。
