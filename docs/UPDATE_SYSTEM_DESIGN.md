# UNI 桌面检查更新方案

状态：客户端与独立 Go 服务已实现初版并完成本地测试；COS、HTTPS 域名、签名和实车安装尚未联调。适用于现有 Flutter 桌面、Android 原生桥接与 `../uni-launcher-ota` 服务。

## 1. 目标与范围

- 设置中新增“关于”页，读取当前实际安装包的版本名称和版本号，提供“检查更新”。
- 默认自动检查：桌面启动稳定后延迟检查；桌面进程运行期间在后台每 5 分钟检查一次；用户可关闭自动检查，手动检查始终可用。只自动检查，下载需用户点击。
- 有新版本时展示版本、大小、发布说明及“下载更新”“稍后提醒”；下载完成且校验通过后自动拉起 Android 安装界面，由用户完成系统安装确认。
- Go 服务负责读取腾讯云 COS 更新清单、按设备条件选择安装包并返回下载信息；更新清单 JSON 和 APK 均存于腾讯云 COS。第一版不做账号、设备标识、强制更新或自动灰度。
- 不覆盖原车系统 OTA，只更新 `xyz.i4o.uni.launcher`。车门、胎压等设备功能是否兼容，以独立的实车测试结论为准。

## 2. 当前工程事实

- 包名 `xyz.i4o.uni.launcher`，`app/pubspec.yaml` 当前为 `0.6.19+33`；这不是所有已安装包实际 `versionCode` 的保证。
- Android `minSdk=24`、`targetSdk=28`，主要车机为 Android 9。当前 `build.gradle.kts` 中普通 debug 和 release 使用本地 `uniLocal` 开发签名；README 同时记录 IP753 测试包曾使用单独签名，必须逐个核对实际已发布包的证书指纹。
- `--split-per-abi` 可让 Flutter 在构建号上追加 ABI 前缀；例如原始构建号 33 可能对应 arm64 APK 的 2033。必须以实际 APK 和已安装包信息为准，不可只比较 `pubspec` 的 `+33` 或版本字符串。参考 [Flutter 构建文档](https://docs.flutter.dev/deployment/android)。
- 已有 `REQUEST_INSTALL_PACKAGES`、网络权限、Flutter `MethodChannel`、文件传输安装流程和 `TransferFileProvider`。更新下载目录独立于传文件目录；共享安装封装可复用，但不能直接假设现有 provider 能安全读取新目录。
- `tools/upload_release.py` 目前只创建 GitHub Release 草稿与校验和，不会自动注册更新服务，也不能证明 APK 的构建来源或签名正确。

顶部现有“外观主题 / 动画效果 / 系统设置”后增加“关于”页签，适配当前深蓝玻璃及其他主题。布局复用 `SettingBlock` 和项目按钮样式。

```text
  自动检查更新                                      [开关]

  贡献者       卢AI玩　 Felix　 十一　 ChainStrong
  项目信息     源码仓库 / 使用许可 / 更新日志
```

“检查更新”的状态：检查中、已是最新、发现更新、网络失败、服务不可用、当前渠道无兼容包。错误显示可重试，不将网络错误显示为已是最新。后台检查发现兼容更新后弹出更新对话框；设置页手动检查复用同一对话框，显示检查过程和结果。设置页显示更新详情和发布说明，更新日志区域随内容自适应高度，达到上限后区域内缓慢自动滚动并支持手动滚动；触摸、滚轮或悬停阅读时暂停，尊重系统减少动态效果设置。下载有进度、取消和失败重试。对话框使用既有主题组件。

自动检查设置默认开启并持久化。网络不可用时不弹窗、不更新“成功检查”时间；默认按 5 分钟周期检查，网络不可用时跳过本次，恢复后下一周期再检查；手动检查允许立即重试。并发请求合并，启动延迟例如 30 秒，防止影响桌面启动。“后台”指桌面进程仍在运行、用户正在使用其他应用；Android 可能冻结或结束进程，进程未运行、系统休眠时无法保证每 5 分钟执行。进程恢复后补查一次，避免短时间连续补发；不承诺被系统终止时仍精确执行。

## 4. 更新流程

1. Android 原生端通过 `PackageManager` 读取当前包 `versionName`、实际 `versionCode`、包名、签名证书集合和系统版本；使用 `Build.SUPPORTED_ABIS` 的有序列表。Android 9 为 API 28；支持低版本时使用兼容 API。展示字段与请求字段均来自已安装包，不硬编码版本。
2. 发起 HTTPS 检查。服务端按发布状态、包名、渠道、SDK 区间、已测试车型平台策略和设备 ABI 顺序选择候选；只返回实际 APK `versionCode` 严格大于当前安装包的结果。车机类型未知或尚未验证时，服务端不把专用平台包当作通用包。
3. 用户同意后下载到应用私有缓存的临时文件；限制大小，显示进度、支持取消。完成后计算 SHA-256，与可信发布元数据对照；核对 APK 包名、实际 versionCode、支持的 ABI、与当前安装包签名兼容性，失败删除临时文件并明确提示。APK 的最终签名和安装兼容性由 Android 安装器检查；解析 APK 元信息不能替代完整签名校验。
4. 下载校验通过后自动拉起系统安装确认界面。Android 8+ 如 `canRequestPackageInstalls()` 为 false，先跳转该应用的未知来源安装授权，再由用户返回继续。使用受限 `content://` URI 和临时只读授权；不用 `file://`。权限和交互以车机实际结果为准。参考 [Android 安装权限](https://developer.android.com/reference/android/content/pm/PackageManager) 和 [Android 文件共享](https://developer.android.com/about/versions/nougat/android-7.0-changes)。
5. 安装器返回成功才记录安装结果；取消、签名不一致、权限拒绝、版本降级、存储不足分别提示。安装可能重启桌面，若系统授权或安装器启动失败，保留已校验文件并显示“重新打开安装”；用户可取消系统确认。升级失败不得卸载原桌面；不自动降级，不清理用户设置。

**签名和安全边界：**SHA-256 可检测下载文件损坏或与元数据不一致，但如果发布元数据和文件同时被恶意替换，单独的 SHA-256 不能证明来源。更新接口和下载必须使用 HTTPS、验证证书，禁止降级明文与不可信跳转；下载地址限制为服务端配置的可信域名。Android 同包覆盖安装要求签名兼容，系统安装器是最终裁决者。当前本地开发签名仅适合受控测试，正式发布前必须核实既有发布证书和密钥保管情况；仓库中的固定开发密钥口令不应被当作生产密钥管理。证书不同的现有安装不能承诺直接覆盖，新签名迁移需另行设计，禁止引导用户卸载以绕过签名校验。

可作为后续增强：离线保护的独立发布密钥对更新清单签名，客户端内置公钥并验证带有效期、渠道及构建号的清单。需要设计密钥轮换、重放防护与已有客户端兼容；签名清单不能代替 APK 签名，也不能在第一版中声称已有该保护。

## 5. Go 服务设计

建议目录 `services/update-server/`，Go 使用 `net/http`、`encoding/json` 和腾讯云 COS Go SDK，反向代理负责 HTTPS；首版读取 COS 上的 JSON 发布清单，校验后在内存中原子替换，并设置有限的刷新周期与失效时间。暂不引入数据库或后台界面。服务运行身份只需指定清单和 APK 对象的读取权限，不拥有 APK 签名私钥或 COS 发布写权限；发布操作由独立的受控身份完成。

```text
UNI 桌面 ── HTTPS 查询 ──> Go 服务 ──读取──> 腾讯云 COS 更新 JSON
    │                         │                         ↑
    │                         └─ 生成临时下载链接         │ 发布流程上传
    └──────── HTTPS 下载 ─────────────────────> 腾讯云 COS APK
```

- `GET /healthz`：只反映进程存活；如需 readiness，另设 `/readyz` 检查清单是否成功加载。
- `GET /v1/updates/check?package=xyz.i4o.uni.launcher&version_code=2033&sdk=28&abis=arm64-v8a,armeabi-v7a&channel=stable&platform=ip753`：`platform` 仅在确有可信本地识别依据时发送；未知发送 `unknown`，不凭 Android 型号猜车型。示例数字不是实际版本承诺。
- 查询长度、整数字段、ABI 列表和渠道必须校验；不记录 VIN、账号、精确位置或设备序列号。默认不发送唯一设备标识，正常访问日志需脱敏并控制留存。无匹配包返回 200 且 `update_available=false`；参数错误 400；清单不可用 503。TLS 终止、限流与最大请求大小在反向代理配置。
- 不使用基于同一 URL 的公共缓存混淆不同设备；第一版 `Cache-Control: no-store`。日后如加缓存，必须将所有选择参数纳入缓存键。

发现更新的示例：

```json
{
  "schema_version": 1,
  "update_available": true,
  "release": {
    "version_name": "0.6.20",
    "version_code": 2034,
    "channel": "stable",
    "published_at": "2026-10-29T00:00:00Z",
    "notes": "修复若干问题。",
    "package_name": "xyz.i4o.uni.launcher",
    "min_sdk": 24,
    "max_sdk": null,
    "platforms": ["ip753"],
    "artifact": {
      "abi": "arm64-v8a",
      "url": "https://example.invalid/cos-presigned-apk-url",
      "url_expires_at": "2026-10-29T01:00:00Z",
      "size_bytes": 20000000,
      "sha256": "<64位十六进制摘要>",
      "signing_cert_sha256": "<发布证书SHA-256指纹>"
    }
  }
}
```

无更新：`{"schema_version":1,"update_available":false,"reason":"up_to_date"}`。无兼容包使用 `reason=no_compatible_release`，不伪装成已是最新。示例 URL 和摘要仅占位。`signing_cert_sha256` 用于发布核对和预检信息，不能只相信服务端返回的指纹。

发布清单中每个 APK 记录其 **实际** versionCode、versionName、包名、ABI、SDK、平台、大小、SHA-256、签名证书指纹、URL、发布状态和说明。同一版本不同 ABI 可有不同 versionCode。候选包按设备 ABI 优先顺序选取，仅选满足安装条件的实际 APK；同 ABI 候选取 versionCode 最大者。无合适 APK 就不提供更新。通用包与 ABI 拆分包的 versionCode 顺序必须在发布前由构建脚本实测，否则可能出现旧 split 包的 code 高于新 universal 包而无法更新。

## 6. 发布与运维

1. 从已审查提交构建签名 APK；通过 `aapt dump badging` 和 `apksigner verify --print-certs` 读取每个 APK 的真实包名、版本、ABI 和证书；对照发布授权证书，不将私钥上传服务。
2. 本地自动测试、模拟器验证、已声明支持车型实车验证；生成 SHA-256、体积、更新说明和构建来源记录。
3. 将 APK 上传到指定腾讯云 COS 存储桶；现有 GitHub Release 可作备用下载，但不能假定车机稳定直连。首次部署需确定存储桶、地域、HTTPS 域名、网络、费用和服务维护者。
4. 先构建并校验清单，然后整体上传替换 COS 上的固定清单对象；不假定 COS 有本地文件系统式的原子重命名。Go 服务完整读取、校验成功后才原子替换内存快照；加载失败时有限期使用上一个有效快照并报警，超过最大陈旧时限则返回 503。发布顺序为先上传并校验 APK，再发布清单。不可覆盖同一版本号的 APK；紧急撤下时更新清单并触发服务刷新，在缓存过期前已签发链接仍可能有效，已安装版本不会自动回退。
5. 最初用测试渠道和测试签名覆盖测试设备；生产渠道只有对应签名和目标车型确认后才开放。灰度发布若后续需要：使用用户知情的本地随机安装 ID 与服务端分组，规定重置和留存策略；第一版不采集也不依赖该 ID。
6. 备份 COS 清单和发布记录、配置健康监控和日志轮转；GitHub 发布脚本可后续增加生成候选清单与校验功能，但保持人工审查及发布确认。服务不拉取私钥、不静默推送、不自动发布 GitHub Release。

## 7. 实现拆分

1. 原生 `UpdateInfo` / Flutter `UpdateState`：读取版本、平台和 ABI，设置页“关于”、自动检查开关、错误和测试替身；无后台安装。
2. Go 服务：清单解析校验、选择策略、HTTP API、健康检查、示例配置、构建和部署说明；端到端测试无外部服务依赖。
3. 客户端请求调度与详情：超时、取消、定时检查、版本过滤；本地 HTTP 测试使用测试注入，不允许生产回落明文。
4. 下载和安装：进度与取消、完整性与 APK 检查、目录隔离、系统授权与安装返回处理；使用测试签名 APK 在模拟器验证。
5. 发布工具、文档、测试渠道及实车验收；验收 QQ/网易云后台播放、导航、全局底栏及安装确认不被遮挡，核对 05 IP753 和 06 E02 各自的包、证书、系统权限与网络。

## 8. 验收与边界测试

- 版本选择：无版本、同版本、升级、已撤回、pre-release、错误包名、未知平台、不支持 SDK、不同 ABI 顺序、split/universal versionCode 高低、签名不一致；并验证服务不会向未知平台推荐专用包。
- 网络：离线、超时、证书错误、重定向到非可信域、错误 JSON、服务 5xx、重复请求、超大响应、定时检查和手动重试；检查不会影响桌面首屏。
- 文件：下载中断和取消、文件长度与 SHA-256 不匹配、恶意文件名、APK 包名/versionCode/ABI/签名不匹配、磁盘不足；失败后不得启动安装器，临时文件可清理；下载完成后校验成功自动启动系统安装界面。
- 安装：授权前后、拒绝授权、取消确认、安装器不可用、正常覆盖、不同签名失败、降级被拒，验证设置和桌面布局保留；系统确认页面在全局底栏下仍可操作。
- 隐私及维护：默认请求不含 VIN、账号或持久设备 ID；服务日志不含敏感数据；更新检查出错不造成重试风暴。真车上的性能、网络和安装行为与模拟器分别记录，不以模拟器替代实车验收。

## 9. 腾讯云 COS 存储与访问设计

默认建议私有存储桶，更新清单与 APK 的真实来源均为 COS：

```text
uni-update-bucket/
  manifests/v1/stable.json
  manifests/v1/beta.json
  releases/0.6.20/arm64-v8a/UNI-0.6.20-arm64.apk
  releases/0.6.20/x86_64/UNI-0.6.20-x86_64.apk
```

- Go 服务使用最小权限的腾讯云运行身份读取指定清单对象并生成 APK 的短期预签名 GET URL；优先使用运行环境的临时凭证或角色，不在源码、APK 或 COS 清单中存放 SecretId/SecretKey。服务身份与发布身份分离，前者无写权限，后者仅可写指定发布前缀。使用 COS Go SDK 的对象读取接口，具体凭证接入按部署环境实现。参考 [COS Go SDK 下载对象](https://cloud.tencent.com/document/product/436/65646)。
- 清单只记录相对 `object_key`，不存短期链接；Go 服务验证 object key 属于允许的 `releases/` 前缀、文件后缀、渠道与发布条目，并根据服务端固定的 bucket/region 配置生成链接，禁止任意 URL 和跨桶读取。客户端只允许 HTTPS 和配置的 COS/CDN 下载域名。
- 链接在用户点击下载前通过检查接口重新获取；响应携带过期时间。下载可能超过签名有效期，应为车机较慢网络留足时间（例如 1 小时，可配置）；过期导致请求或续传失败时重新检查并获取新链接，再在确认文件身份和服务端支持 Range 的前提下续传，否则删除临时文件重新下载。不得把带签名的完整 URL 写入日志或长期持久化。参考 [COS 预签名 URL](https://cloud.tencent.com/document/product/436/68284)。
- COS 清单按版本整体上传，服务端以可配置周期刷新（例如 60 秒），设置最长陈旧时间（例如 10 分钟）；首次无有效清单或快照过期后返回 503 而非误报最新。监控上次成功刷新时间和错误计数；部署时必须明确 COS 凭证续期与刷新失败处理。撤回只阻止后续签发，不能撤销客户端已获取且仍有效的 URL，缩短 TTL 可降低该窗口；已经下载的包也无法远程撤回。
- 客户端实际下载直连 COS，不经过 Go 转发 APK，避免服务带宽成为瓶颈。预签名 URL 是持有者可用的临时访问凭证，第一版公开更新检查接口仍可被调用并获取链接，必须结合限流、短有效期、COS 流量监控和费用告警，不能将其称为用户身份认证。
- 如希望简化架构，可由用户明确选择将**仅发布目录**配置公有读，并用固定 HTTPS 链接；任何人可访问，需承担公开下载和流量风险。不要将整个存储桶误设为公开；[腾讯云说明](https://cloud.tencent.com/document/faq/436/30740)。若采用 CDN/自定义域名，确认域名、HTTPS 证书、回源权限、缓存与鉴权规则兼容方案；腾讯云对部分存储桶默认域名的 APK 访问有使用限制，按[官方说明](https://cloud.tencent.com/document/product/436/102509)配置并实际测试。

```json
      "size_bytes": 20000000,

      "signing_cert_sha256": "<发布证书SHA-256指纹>"
    }]
  }]
}
```

每个 ABI 的实际 `version_code` 分别记录在 `artifacts` 中；返回客户端时取所选 artifact 的值。配置项包括 COS bucket、region、清单 object key、允许前缀、下载域名、清单刷新/最大陈旧时间、签名 URL 有效期和服务监听地址。以上值不写死在仓库，实际 bucket、region、域名和凭证尚待部署时配置。

## 10. 更新对话框设计与调度细节

交互设计稿：[设计预览](../design/update-dialog/index.html)。预览中的版本、大小、更新内容和进度为示例，状态切换仅演示 UI，不会下载或安装。

- 默认启用后台检查：进程存活时每 5 分钟检查一次；自动检查网络失败静默显示在设置页，不弹出错误。手动检查立即执行，并与正在进行的自动检查合并。
- 自动检查发现新版本后弹出同一个更新对话框；已经展示或正在下载时不得重复弹窗。同一版本点击“稍后提醒”后保留版本标识，本方案暂定 24 小时后再次提醒；后台仍每 5 分钟检查，发现更新的更高版本可立即提醒，设置页手动检查可随时打开。
- 对话框依次支持检查中、发现新版本、下载进度、校验中、系统安装确认、已是最新和失败重试。更新日志短时按内容自适应高度，超出上限时区域内缓慢自动往返滚动；触摸或鼠标阅读时暂停并允许手动滚动，系统设置减少动态效果时不自动滚动。进度包括百分比及已下载/总大小；用户可取消下载。下载完成后校验大小、SHA-256、包名、实际版本、签名兼容性，通过后自动拉起 Android 系统安装确认。缺少未知来源授权时跳转授权，用户返回并确认授权后继续安装；不进行静默安装。
- 若当时桌面 Activity 不在前台，不从后台强行启动 Activity 或伪装成已展示：将新版本置为待展示，桌面恢复前台时弹出同一对话框。系统安装界面必须位于可操作区域，且与车机全局底栏的兼容性需实测。
- 对话框按当前主题绘制，保持全局底栏可见；深蓝玻璃使用四角框线和半透明背景，圆角遵循设置。真实版本号从安装包读取。

## 11. 关于页贡献者

- 应用随包预置 `卢AI玩`、`Felix`、`十一`、`ChainStrong`，离线首次打开也可显示。远程名单更新成功且完整校验后整体替换当前名单；失败、无权限、超时或 JSON 无效时保留上次有效缓存，若无缓存则回退内置名单。顺序按 JSON 显示，不将空列表误当作有效替换，除非将来明确设计允许清空。
- 贡献者名单单独存放在 COS，例如 `content/contributors.json`。默认使用现有 Go 服务提供 `GET /v1/contributors`，Go 从配置的固定 COS 链接或对象键读取并短时缓存；车机仅访问 HTTPS 服务，不持有 COS 密钥。若 COS 链接设为公有读，也可后续直接读取该固定 HTTPS 链接，配置和下载域名校验仍须明确。不得允许远程 JSON 指定任意请求地址。
- 数据只含公开展示的名字，不收集用户信息；客户端与服务端限制条数（例如 100 人）、单个名字长度（例如 1–40 个字符）、响应大小（例如 64 KiB）并将名字作为纯文本显示，防止富文本注入；对重复、非法或超限条目按整份校验失败处理。默认打开关于页时可异步刷新，且至少间隔 24 小时；与更新检查的 5 分钟周期互不影响。缓存包含成功时间与版本，异步读取不阻塞关于页。
- 示例：`{ "schema_version": 1, "contributors": ["卢AI玩", "FF", "十一", "ChainStrong"] }`。实际 COS 地址、访问权限、缓存周期及维护方式待部署配置，当前设计稿尚不执行网络请求。
- 更新图标采用向上箭头与循环线条组合，使用当前主题强调色；背景为透明，仅作为状态示意，与主题四角框线协调。

## 12. 当前实现和待联调事项

- 客户端构建时通过 `UNI_OTA_URL`、`UNI_OTA_DOWNLOAD_HOSTS`、`UNI_OTA_PLATFORM` 配置，未配置时不会连接服务；具体命令见 `app/README.md`。下载支持身份绑定、HTTP Range、服务端忽略 Range 时重新下载、链接过期后重新检查以及 SHA-256 校验。
- 下载后原生端预检包名、安装版本和签名，再打开系统安装器；无法从仅启动安装器推断用户最终是否安装成功，当前界面不宣称安装成功。授权后回到桌面会尝试继续安装。签名轮换、ABI 细节以及系统确认页均需在目标设备验证。
- Go 服务目前通过一个 `manifest_key` 读取清单，若使用多个渠道，需将渠道条目放在该清单中或部署多套服务；不是自动加载不同渠道文件。COS STS 自动续期尚未实现，临时凭证须由部署平台轮换并重启服务。
- 已有本地测试覆盖版本选择、不可用/陈旧清单、贡献者回退、断点续传、错误范围、服务器忽略 Range 和摘要不符。当前没有真实 COS 凭据、已部署 HTTPS 入口或连接的模拟器/车机，尚不能宣称 COS 下载、系统安装及车机签名已联调通过。
