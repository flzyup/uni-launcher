# 跨桌面能力核对与验收

基准：CarDesk main 的 4e126788；UNI 当前功能分支。CarDesk 仓库当前未找到明确代码复用许可。本阶段不复制其源码或素材；直接移植前需确认授权与分发条款。

## 第一批：音乐和胎压

- 音乐按 MediaSession token 区分会话；自动选源保留当前暂停会话；同会话暂停时保留最近歌曲文字及封面。会话不可用时可展示上次歌曲摘要，标明并非实时数据。缓存写入按歌曲变化或至少 30 秒间隔，歌词和封面不持久化。
- 真实播放器可能销毁会话或让多个会话同时播放，需要验证 QQ、网易云与原车音源；现阶段不承诺无会话时无缝恢复播放。
- 系统设置提供只读胎压诊断，复用现有四轮字段与原始数据，不新增车辆写入。原车界面、单位、轮位需逐车对照，不能直接套用另一车型映射。
- 离线验证：`python3 tools/test_media_session_policy.py`、`python3 app/native-tests/tools/test-netease-adapter.py`、`python3 app/native-tests/tools/test-official-media-bridge.py` 和 `cd app && flutter test`。

## 车机验收

1. 停车状态使用网易云、QQ 各播放一首，查看卡片和底栏；暂停至少 30 秒，再恢复、切歌和切换播放器，检查歌曲、封面及播放器名称是否闪变。
2. 检查方向盘切歌、仪表歌名和播放状态；播放器被系统关闭后检查“上次播放”标注，并验证重新建立会话后的控制。
3. 打开系统设置中的“胎压数据诊断”，记录车型、车机版本、四轮原车显示、UNI 显示、原始值、来源及不可用原因。不同车型分别对照。

## 后续阶段

- 车身门窗、发动机舱和尾门：界面已预留字段，部分未知时不会显示全部关闭。原车数据源、区域和值的含义未在 IP753 上确认，不发布猜测的开关状态。验收需逐个开关车门和舱盖，与原车界面、各字段原始值及断连情况对照。
- 地图：已有高德官方标准广播和 yh 修改版巡航红绿灯适配，数据 5 秒过期。Android 模拟器合成广播通过 13 项检查；实际 yh 多方向、枚举和更新频率需在停车条件下采集核对。车道引导不等于红绿灯方向，不互相推断。百度和腾讯内部信号不证明跨进程可用，详情见 `analysis/navigation-provider-evidence.json`；目前没有把候选接口当作可用功能。
- 天气：原车当前天气与 Open-Meteo 多日预报保持来源区分，地区匹配支持区县、父级和城市回退。新增请求代次校验，避免 A→B→A 城市切换后的旧响应覆盖新结果；新请求取消旧请求并清理已取消队列，最后一个监听者离开时解绑服务、停止重试并关闭工作线程。网络调用退出仍受连接及读取超时约束。本地测试覆盖城市匹配和请求代次；实车还需验证原车返回的地区、网络连通和多日预报。
- 性能和悬浮分屏：现有地图嵌入与全局底栏均涉及系统窗口和车型兼容，本轮未直接替换；需要车机上的帧率、内存与其他应用遮挡证据后再确定是否改造。
- 代码来源：Cardesk 未发现明确复用许可，以上实现使用独立实现及现有 UNI 代码；不复制其代码或素材。
