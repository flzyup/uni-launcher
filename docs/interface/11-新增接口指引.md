1. **数据只有一个来源**：`LauncherRuntime` 单例（`LauncherRuntime.java:90`）+ `SharedPreferences("launcher")`（`:104`）。任何引擎都别自己存一份状态。

## 2. 扩展类型 A：新增一个通道方法（Dart ↔ 原生，一问一答）

**目标**：Dart 调 `xyz.i4o.uni.launcher/platform` 上的一个新方法，拿到 Map/List/标量。

改动点：

| 侧 | 落点 | 说明 |
|---|---|---|
| 原生 | `MainActivity.configureFlutterEngine` 的 `channel.setMethodCallHandler`（`MainActivity.java:103-168`） | 在 `else result.notImplemented()`（`:166`）之前插一个 `else if("yourMethod".equals(call.method))` 分支 |
| 原生 | 参数校验 | 字符串参数参考 `action` 的 8192 上限（`:149`）；数字参数参考 `otaInterval` 的白名单校验（`:119`，非法值直接 `IllegalArgumentException`） |
| 原生 | 返回值 | 返回 Map 的形状参考 `otaInfo`（`:115`，`HashMap<String,Object>` 直接 `result.success`） |
| Dart | `app/lib/platform/native_gateway.dart:22` 的 channel 常量 + 新方法 | 参考 `pickWallpaper`（`:56`）、`setDesktopPage`（`:65`） |
| Dart（独立能力） | 自建类，仿 `app/lib/platform/cluster_lyrics.dart:105-106` | 用同一个通道名也可以，但异常要显式吞成默认值（`:119-123`） |
| 原生（面板也要用） | `GlobalDockService.java:239-248` 同步加分支 | 不加就只能在主窗口用 |

步骤：

1. 原生加分支，返回值只放可 JSON 化的基本类型/集合。
2. Dart 加方法，返回类型与原生一致（`invokeMapMethod` / `invokeListMethod` 不要和 `invokeMethod<Map>` 混）。
3. 需要跨引擎可用时，同步 `GlobalDockService` 的分支。
4. 写 Dart 单测 mock 掉通道（见第 7 节）。

必须验证：

- `flutter analyze --no-pub` 干净。
- Dart 单测：`TestDefaultBinaryMessengerBinding.instance.defaultBinaryMessenger.setMockMethodCallHandler(channel, handler)`，真实写法见 `app/test/cluster_lyrics_test.dart:9-15`。
- 实机：`adb shell dumpsys activity xyz.i4o.uni.launcher/.MainActivity --uni-state` 输出 `UNI_STATE={…}` 而不是 `UNI_STATE_UNAVAILABLE`。

典型翻车：

- Dart 侧抛 `MissingPluginException` → 方法名拼错，或在底栏/面板引擎里调了只在主窗口实现的方法（对照第 1.3 第 2 条）。
- 原生 `result.error("unavailable","操作暂不可用",null)`（`MainActivity.java:167`）被 Dart 当 `PlatformException` 吞掉，界面「什么都没发生」——加日志或让 Dart 把 message 显示出来。

## 3. 扩展类型 B：新增一个 action（命令式接口）

**目标**：界面点一下 → 发一条 `{"action":"xxx", "value":..., "enabled":...}` → 原生执行并让快照重发。

改动点：

| 侧 | 落点 | 说明 |
|---|---|---|
| 原生（业务） | `LauncherRuntime.handleOnMain`（`LauncherRuntime.java:288-483`） | 命令白名单就在这一长串 `if("…".equals(action))` 里；新增就加一个分支 |
| 原生（窗口/权限相关） | `MainActivity.handle`（`MainActivity.java:262-287`） | 需要弹权限、开 Activity、动导航栏的放这里；它先让 `GlobalDockService.handleCommand` 试一次（`:263`） |
| 原生（底栏/面板独占） | `GlobalDockService.handleCommand`（`GlobalDockService.java:89-190`） | 面板内动作（`show-dock-panel`、`panel-ready`、`dismiss-dock-panel`、`system-back`、`show-recents`…）都在这里 |
| Dart | `LauncherController.command`（`app/lib/controller/launcher_controller.dart:313`）→ `gateway.action`（`app/lib/platform/native_gateway.dart:37-47`） | Dart 只负责 JSON 编码，不做业务判断 |

步骤：

1. 在 `handleOnMain` 加分支：先校验参数，再改状态或写 prefs，最后确保有一次 `publish()` 让界面刷新（80 ms 合并，`LauncherRuntime.java:505-524`）。
2. 布尔开关类命令的范式：`rename-app`（`:292`，写 `appNames` 并回包）、`desktop-page`（`:301`）、`demo-mode`（`:304`）。
3. 需要在主窗口做的事（如 `calendar-access` 弹权限）放 `MainActivity.handle`，参考 `MainActivity.java:268-273`。
4. 面板里能触发的新命令，检查 `GlobalDockService.handleCommand` 是否也要一条；`show-dock-panel` 的页签 value 必须命中白名单（`GlobalDockService.java:352`：`apps, climate, media, vehicle, navigation, music-picker, uni-menu, transfer, cleaner`）。

必须验证：

- Dart 单测用 `FakeGateway` 记录命令（`app/test/fake_gateway.dart:38-52` `commands` 列表），断言 action 与参数。
- 真机验收：`tools/car-verify.ps1`（`-SkipBuild` 只装已签名包）或 `tools/dev-local.ps1`（模拟器回路）。

典型翻车：

- 命令改了状态但界面不动 → 忘了 `publish()`，或者改动没让 `designRevision`/`mediaRevision` 推进（`LauncherRuntime.java:226-233`）。
- 命令在面板里无效 → 分支写在 `LauncherRuntime` 里没问题，但面板的 action 是发给 `GlobalDockService` 的 `…/platform` 通道（`GlobalDockService.java:236`），它会先走 `handleCommand` 再落到 runtime。

## 4. 扩展类型 C：新增 EventChannel 事件（原生 → Dart 推送）

**目标**：原生主动推一条状态给 Dart，不用轮询。

改动点：

| 侧 | 落点 | 说明 |
|---|---|---|
| 原生 | `MainActivity.configureFlutterEngine`（`MainActivity.java:169-178`） | `new EventChannel(messenger,".../your-events").setStreamHandler(...)`；`onListen` 里立刻补一包（`:171`），`onCancel` 里清 sink 并把游标重置（`:172-177`） |
| 原生（轻量命令） | 反向 `MethodChannel.invokeMethod`（`MainActivity.java:102`、`:489`） | 只需要「敲一下」而不是持续流时用这个，`ota-events` 就是这么做的（`app/lib/ota/update_controller.dart:18-19`） |
| Dart | `app/lib/platform/native_gateway.dart:23`、`:33-35` | 约定：`events` 通道载荷是 **JSON 字符串**，这里统一 `jsonDecode` |
| Dart（独立流） | 仿 `app/lib/platform/audio_spectrum.dart:14-15` | 载荷是 **Map**：`xyz.i4o.uni.launcher/spectrum`（`SpectrumBridge.java:69`） |

步骤：

1. 原生建通道，明确载荷形态（JSON 字符串 or Map），写进注释。
2. Dart 侧解包时形态必须与原生一致；`events` 上永远拿不到裸 Map（`native_gateway.dart:33-35` 已经 decode 过）。
3. 推送频率要自己节流：参考 `SpectrumBridge` 的 `publish`（`SpectrumBridge.java:140-143`）与状态推送策略（`:145-152`）。
4. 订阅生命周期：`onListen` 必须立即发一包，否则 Dart 首帧空等。

必须验证：

- Dart 单测用 `setMockStreamHandler`（`flutter_test` 的 `test_default_binary_messenger.dart:359`，handler 用 `MockStreamHandler.inline(onListen: …)`，定义在 `packages/flutter_test/lib/src/mock_event_channel.dart:17-29`）。
- 实机：`adb logcat` 只看该模块 TAG，确认推送频率符合预期（空闲时应该安静）。

典型翻车：

- 在 `events` 上加 Map 壳 → Dart 侧 `value as String` 直接崩。
- 忘了 `onCancel` 清 sink → Activity 销毁后 `sink.success` 抛异常刷屏（参考 `MainActivity.java:504-506` 的清理顺序）。
- 多引擎重复注册同一 EventChannel 名 → 面板那份没人订阅却仍被推送，浪费 CPU。

## 5. 扩展类型 D：新增一个快照字段

**目标**：让新数据跟着桌面快照一起到 Dart，兼容增量传输。

改动点：

| 侧 | 落点 | 说明 |
|---|---|---|
| 原生（生产） | `LauncherRuntime.buildSnapshot`（`LauncherRuntime.java:165-241`） | 字段挂到某个分组里；`partial` 决定 Dart 是否合并（`:216`） |
| 原生（增量） | 分组游标 `StaticCursor.apps/design/media/settings`（`:71-73`、`:200-221`） | 静态分组只在游标落后时出现；每次都变的字段别塞静态分组 |
| 原生（数据源） | adapters（`:113-125`）、监听器（`:485`、`:495`） | 新数据源要在 `addListener` 时启动、最后一个 owner 离开时停止 |
| Dart | `LauncherController._receive`（`app/lib/controller/launcher_controller.dart:188-297`） | `partial` 合并逻辑；上一包遗留字段必须登记到 `_carriedKeys`（`:180`）/`_carriedMedia`（`:186`），否则第二包就丢 |
| Dart（展示） | `app/lib/widgets/…` 通过控制器读 | 不要在 widget 里再解析 JSON |

步骤：

1. 原生把字段放进 `buildSnapshot` 的对应分组，字段名定死并写注释。
2. 判断它是「每次刷新都变」还是「结构变化才变」：前者放遥测（一直发），后者挂游标/指纹（`design.hashCode()` 等，`:226-233`）。
3. Dart 侧只做「缺键时沿用上一包」的登记，别在 Dart 端重算业务值。
4. 大字段不要混进增量包：超过 65536 字符会打 `UniPerf` 警告（`MainActivity.java:222-223`），说明有 payload 泄进 delta。

必须验证：

- `adb shell dumpsys activity xyz.i4o.uni.launcher/.MainActivity --uni-state` 用的是全量快照（`updateSnapshotFull`，`MainActivity.java:227-231`），字段应当出现在 `UNI_STATE=` 里；注意 `dump` 只挑选白名单键输出（`:323-330`），新字段要加进那个名单才能在 dumpsys 里看到。
- Dart 单测：给 `FakeGateway.state` 加字段（`app/test/fake_gateway.dart:6-35`），断言 widget 渲染。

典型翻车：

- 首包有、第二包没了 → `partial` 合并没登记遗留键（`launcher_controller.dart:180-186`）。
- 界面永远不刷新 → 字段只在 `snapshot()` 里算，没跟 `publish()` 的 80 ms 合并（`LauncherRuntime.java:505-524`）。
- 空闲时也满帧推送 → 时间戳签名去重失效，检查字段名是否以 `AtMs`/`AtElapsedMs` 结尾（`MainActivity.java:304-307` 的正则会把它们归一）。

## 6. 扩展类型 E：新增后台服务 / 广播接收器

**目标**：开机、定时或外部广播触发后台逻辑。

改动点：

| 落点 | 说明 |
|---|---|
| `AndroidManifest.xml` L65–L79 | 服务与 receiver 都在这一段；`exported` 显式写，接系统广播的 receiver 只能 `true` |
| 权限 | 用到的权限要在 L2–L48 声明；OEM/特权类见 10 号文档 2.3，拿不到要在代码里降级而不是崩 |
| 代码 | 服务放根包（`GlobalDockService`、`OtaBootService`）或 `integration/`（`ClusterLyricsService`、`MediaAccessService`） |

步骤：

1. manifest 加组件，写清 `android:exported`；只在确实需要在直接启动阶段运行时才加 `directBootAware="true"`（现有只有 `GlobalDockBootReceiver`，L74）。
2. 系统广播处理要包 try/catch：发广播可能 `SecurityException`，参考 `OtaBootReceiver.java:33` 只打日志不崩。
3. 处理超过几秒的回调必须 `goAsync()` + 显式 `finish()`，参考 `GlobalDockBootReceiver.java:32-41`。
4. 需要延迟/重试就用 `AlarmManager` + 专用 receiver（`GlobalDockBootReceiver.java:5` → `DefaultHomeAlarmReceiver.java:10`），别在 `onReceive` 里 `sleep`。
5. 前台服务必须 `startForeground(id, notification)`，参考 `GlobalDockService.java:195-198`（id 753）；同时要有 `FOREGROUND_SERVICE` 权限（manifest L22）。
6. 直接启动阶段不能读用户存储；用户数据相关逻辑放到 `BOOT_COMPLETED`/`USER_UNLOCKED` 分支（`GlobalDockBootReceiver.java:15` 只在 boot 分支启动服务，就是这个原因）。

必须验证：

- `adb shell dumpsys activity services <包名>` 能看到服务在跑（本机实测：服务未启动时该命令输出为空，`待确认` 车机上 `dumpsys activity service <包名>/.<服务类>` 的形式是否可用——见 12 号文档）。
- `adb logcat -s UniDock -s UniHome -s UNI-Startup` 看启动链日志。
- 冷启动一次完整开机流程：`tools/car-verify.ps1`（含冷启动 ×3）。

典型翻车：

- 服务被系统拦：Android 9 上后台 `startService` 会失败，必须 `startForegroundService`（`GlobalDockService.java:54` 已处理 26+ 分支）。
- 悬浮窗服务起来但不可见 → 缺 `SYSTEM_ALERT_WINDOW`（`Settings.canDrawOverlays` 判断在 `:53`），不是服务问题。
- 开机恢复不生效 → 看 `UniHome current home=` 日志（`DefaultHomeGuard.java:30`）与实际 home 组件名，别盲改代码。

## 7. 扩展类型 F：副屏 / 原生视图（照 `integration/display` 的四层来）

这是本仓库唯一「用原生 View 而不是 Flutter 绘制」的路径：目标屏幕的窗口管理器在别的 display 上，起第二个引擎只为几行字不划算（`ClusterLyricsView.java:14-25` 的注释就是设计依据）。

四层分工（现有实现，新增同类能力照抄分层）：

| 层 | 职责 | 现有文件 | 关键行 |
|---|---|---|---|
| 1. 决策纯函数 | 输入全部显式传入，无 Android 依赖，可直接单测 | `integration/display/DisplayPicker.java` | `pick(ids,names,presentation,wantName,wantId)` `:31`；id 精确匹配 `:38`；名字唯一才用 `:47`；`firstPresentation` `:63`；`firstSecondary` `:73`；`label()` `:82` |
| 2. 状态牌 | 跨层共享的不可变状态快照，谁都能读，不持有 View/Context | `integration/lyrics/LyricCast.java` | `static volatile State` `:16`；`positionAt` `:47`；`publish` `:66`；`cursorAt` `:81` |
| 3. 视图 | 纯绘制，输入是状态 + 时间戳 | `integration/display/ClusterLyricsView.java` | `configure(textSizePx, accent, muted, background)` `:53`；`setState(state, nowMs)` `:63`；`ROW_COUNT=3` `:27` |
| 4. 服务 | 生命周期、权限、窗口、重试、状态上报 | `integration/display/ClusterLyricsService.java` | prefs `cluster-lyrics` `:48`、键 `:49-53`；`apply` `:129`；`status` `:164`；`displays` `:181`；`reconcile` `:211`；`attach` `:262`（`TYPE_APPLICATION_OVERLAY` `:287`）；`detach` `:317`；帧循环 `:355` |
| 桥 | Dart 只发配置、只读状态，从不发帧 | `MainActivity.java:152-165` + `app/lib/platform/cluster_lyrics.dart:105-158` | 三个方法：`clusterLyricsDisplays/Status/Apply` |

步骤：

1. **先写第 1 层**（纯函数）+ JUnit 测试，输入用 id/名字列表，输出目标 id。参考 `app/android/app/src/test/java/xyz/i4o/uni/launcher/integration/display/DisplayPickerTest.java`（本机实测 `OK (6 tests)`）。
2. **再写第 2 层状态牌**：只有不可变数据 + 时间基准；`LyricCast` 是 `static volatile`，因为桌面卡片和副屏视图要读同一份（`LyricCast.java:16`）。
3. **第 3 层视图**只做 Canvas 绘制：所有尺寸/颜色通过 `configure` 传入，`setState` 不带副作用（`ClusterLyricsView.java:53`、`:63`）。
4. **第 4 层服务**负责：读/写 prefs、判断 `Settings.canDrawOverlays`、建窗口、失败重试（1000–30000 ms，`ClusterLyricsService.java:56-57`）、把状态写进 `report` 字符串（`:305`）。
5. 状态上报**不用日志**：`ClusterLyricsService` 全文没有 `Log.*`，界面靠 `report`/`status` 拿到原因（`:147`、`:220`）。新增同类服务照做，否则实车上没有 adb 日志可查。
