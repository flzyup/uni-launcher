# 05 · 副屏投射（歌词投屏）

把歌词窗口加到**另一块屏幕自己的窗口管理器**上。不是"把歌词发给仪表"，不是投屏协议，也不需要车厂接口。

本文件是接口契约：设置页 ↔ 原生服务 ↔ 目标屏幕三方之间流动的键、值域、失败语义。行为细节与上车验证顺序见 `docs/CLUSTER_LYRICS_CAST.md`。

> 行号以当前 `main` 分支源码为准；改动这三个 Java 文件后需要同步本文件的「契约」章节（`ClusterLyricsService.java` 702 行、`ClusterLyricsView.java` 266 行、`ClusterPanelGeometry.java` 88 行）。

---

## 1. 数据流

**一份文档，两个消费者（0.7.8 起）**：卡片和投屏以前各挑各的来源——卡片读 `snapshot.lyrics` 原始 LRC 文本自己解析，投屏读 `snapshot.lyricTimeline`（Java 编译好的时间轴）。同一首歌会给出两个答案，见第 8 节「两份歌词文档」。现在两边都以 `lyricTimeline` 为准，`lyrics` 只在没有时间轴时兜底（`app/lib/widgets/lyrics_view.dart:63`、`app/lib/model/lyrics.dart` 的 `Lyrics.fromTimeline`）。

```
MediaSession（音乐 app）
  └─ MediaAdapter.snapshot()                    integration/MediaAdapter.java:394
       ├─ snapshot.lyricTimeline               → Flutter 歌词卡片（同一份文档）
       ├─ snapshot.lyrics                      → 仅作为无时间轴时的兜底文本
       └─ LyricCast.publish(...)               :447
   ┌──────────────┴───────────────┐
   │ 前台快照                       │ 服务自取
   │ MainActivity.publish()        │ ClusterLyricsService.pump()
   │  :293（sink==null 直接返回）    │  :376（每 700ms，无 UI 也跑）
   └──────────────┬───────────────┘
                  ↓
        LyricCast.state()（进程内静态）
                  ↓
   ClusterLyricsService.tick()  :592 → ClusterLyricsView.onDraw()
```

**为什么服务要自己取数**：`MainActivity.publish()` 在 `sink==null` 时直接返回（`MainActivity.java:301`），而车机上用户 99% 时间在音乐 app 全屏，Flutter 侧没有监听者。只靠快照喂 `LyricCast`，仪表上的歌词会停在"打开桌面那一刻"。`pump()` 走 `LauncherRuntime.pumpMediaCast()`（`LauncherRuntime.java` 中 `pumpMediaCast`），只取媒体分组、不扫应用、不构建设置目录，并在适配器已被 `stop()` 时重新 `start()`（`MediaAdapter.started()`）。

| 项 | 值 | 位置 |

| flags | `NOT_FOCUSABLE \| NOT_TOUCHABLE \| NOT_TOUCH_MODAL \| LAYOUT_IN_SCREEN \| LAYOUT_NO_LIMITS \| HARDWARE_ACCELERATED`（`NOT_TOUCHABLE` 让手指穿过面板落到下面的应用上） | `:511-516` |

| width / height | `ClusterPanelGeometry.width/height` | `:497-499` |
| title | `UNI 歌词投屏`（`dumpsys window windows` 里按它找） | `:522` |
| 密度 | `target.getRealMetrics(metrics).density`，`<=0` 兜 1 | `:483-484` |

`params.x/y` 是**面板左上角**，而存储的 `xRatio/yRatio` 是**面板中心**。中心是拖拽的自然语义（往中间一丢就居中，与宽度无关），左上角是窗口参数的语义。换算与边界收拢全在 `ClusterPanelGeometry.origin`（`:76`）。

### 定位公式（三方共用）

```
width  = round(displayW * clamp(widthRatio, 0.2, 1.0))           ClusterPanelGeometry.java:54
height = round(max(8, fontSp * density) * 1.62 * clamp(rows,1,3)) :61
centre = (round(displayW * xRatio), round(displayH * yRatio))     :82-83
origin = clamp(centre - size/2, 0, display - size)                :84-85
```

同一套公式在 Dart 侧有一份孪生实现 `app/lib/model/cluster_layout.dart`（`ClusterLayout.origin/previewBlock/ratiosForCentre`），供设置页的预览框使用。**两边任何一侧单独改动都会让"预览里拖到哪里、仪表上出现在哪里"错位**，因此两侧都有单元测试钉住同一组数字：`ClusterPanelGeometryTest.java` 与 `app/test/cluster_layout_test.dart`。

## 4. 通道契约

三条方法都在 `xyz.i4o.uni.launcher/platform`（`MainActivity.java:152-165`）。

| 方法 | 入参 | 返回 |
| --- | --- | --- |
| `clusterLyricsDisplays` | 无 | `List<Map>{id,name,presentation,width,height,densityDpi,label}` |
| `clusterLyricsStatus` | 无 | `Map`（见下表） |

## 5. 渲染契约（`ClusterLyricsView`）

| 参数 | 含义 | 位置 |
| --- | --- | --- |
| `textSizePx` | 当前行字号（已乘密度） | `:83` |
| `rows` | 1–3 | `:84` |
| `accent` / `muted` | 高亮色 / 次要行色（由 accent 混出） | `:85-86` |
| `background` | 底板颜色，alpha 0 = 不画底 | `:87` |
| `style` | `STYLE_PLAIN(0)` / `STYLE_PILL(1)` / `STYLE_GLOW(2)` | `:88` `:46-48` |

行语义：

| 状态 | 画什么 | 位置 |
| --- | --- | --- |
| 无时间轴 | `等待播放` / `正在获取歌词` / `当前音源未提供歌词`（三态，`:118-126`） | `:117-131` |
| 间奏 | 三行时上一句（0.74 倍、0.42 alpha）+ 三点脉冲 + **下一句淡出提示**（0.7 倍、0.5 alpha） | `:126-152` |
| 正常 | 上一句 0.72 倍 / 当前行 1.0 倍 / 翻译或下一句 0.7 倍 | `:137-150` |
| 逐字 | 当前行先画暗色底字，再用 `sungPrefix()` 长度裁切画高亮字 | `:202-247` |

间奏行里 `Cursor.text` 是空的，上一句在 `Cursor.previous`、下一句在 `Cursor.next`（`LyricTimeline.at` 的间奏分支）。只读 `text` 会在间奏时段画出三个孤立的点——这正是"面板像没拿到歌词"的观感来源之一。

逐字填充的边缘是渐变而非硬切（`drawText` 里的 `LinearGradient` + `FEATHER = 0.55 × 字号`）：仪表是哑光面，硬边看起来像渲染错误。只有拿到词级时间轴（`LyricTimeline.Cursor.wordTimed`）才会出现"半句高亮"；纯 LRC 只有行级时间，整行一次性变色——这是数据决定的，不是渲染器偷懒。

行高 = `fontSize × 1.62`，与 `ClusterPanelGeometry.ROW_SPACING` 同一个常量来源（Java `:21`，Dart `ClusterLayout.rowSpacing`）。

## 7. 屏幕选择

`DisplayPicker.pick(ids, names, presentation, wantName, wantId)`（`DisplayPicker.java:31`）：id 精确命中 → 唯一名字命中 → `NONE`。同名多屏**不猜**，因为猜错就是把歌词糊到副驾屏或倒车影像上。

`displays()`（`:304`）返回所有有效屏幕，附带 `presentation = 是否在 DISPLAY_CATEGORY_PRESENTATION 里`。

Dart 侧"只点开关"的自动目标（`cluster_lyrics_settings.dart` 的 `_firstSecondary`）：**presentation 优先 → display 0 → 任意 id>0**。早先的"任意 id>0"在测试车上选中了 UNI 自己的虚拟导航屏（`UNI Live Navigation 0`，id 3/4/5 会变），歌词就落在用户正在看的那块屏上。这个坑必须靠 presentation 优先来避免。

## 8. 已知边界

- **屏幕 id 不稳定**：重启/休眠后 id 会变，所以持久化 name+id 成对，并靠 `DisplayListener` 重新解析。
- **`lastReport` 只在内存**：进程重启回 `未启用`，Dart 侧靠轮询纠正。
- **私有屏不可绘**：目标屏若带 `FLAG_PRIVATE`，`addView` 抛 `BadTokenException`，`report` 会带原因。
- **仪表通常是独立系统**：`displays()` 里看不到仪表时，第三方没有任何路径画上去（详见 `docs/CLUSTER_LYRICS_CAST.md` 第 4 节的兜底路线）。
- **只画文字**：没有逐字时间轴时不会有卡拉 OK 效果。`LyricCatalog` 现在能拿到网易云 KRC（逐字），实测 `每天每天` / `底牌` 都带 `w[]`；拿不到时退回行级 LRC。
- **25 fps**：`FRAME_MS = 40`（`:76`）。暂停即停帧，最后一行留在屏上。

### 两份歌词文档（已修）

同一首歌曾经在磁盘上有两份互不相认的歌词，两个消费者各读一份：

| | 桌面卡片 | 投屏面板 |
| --- | --- | --- |
| 字段 | `snapshot.lyrics`（原始 LRC 文本） | `snapshot.lyricTimeline`（编译后的时间轴） |
| 解析者 | Dart `Lyrics.parse` | Java `LyricTimeline` |
| 缓存目录 | `files/media-lyrics/<hash>.lrc` | `files/lyric-timeline/<hash>.lyric.json` |
| 缓存键 | 旧的 `LyricsResolver.key`：`round(时长/1000)` | `LyricCatalog.key`：`floor(时长/1000)` |

两个后果，都在设备上复现过：

1. **同一时刻两边显示不同句子。** `每天每天` 的 LRC 有 `[00:00.00] 作词 : 娃娃` 三条 credit 行，而网易云 KRC 的第一行在 `t=17560`（不带 credit）。00:11 时卡片高亮「编曲 : 方大同」，面板在间奏——只画出三个点。
2. **投屏更晚拿到歌词。** 两个键一个 `round` 一个 `floor`，还各自做了不同的标题归一化，同一首歌哈希成两个名字：文本缓存命中不了，时间轴就得走网络，面板于是比卡片晚 1–3 秒才有内容。

修法是消掉"两份"本身：

- `LyricsResolver.key` 直接委托 `LyricCatalog.key`（`LyricsResolver.java:177`），两个缓存同一个键。
- 卡片优先读 `lyricTimeline`，原始文本只作兜底（`app/lib/widgets/lyrics_view.dart:63`、`app/lib/model/lyrics.dart` 的 `Lyrics.fromTimeline`）。
- 词级时间轴丢掉的 credit 段用 LRC 的行补回来（`LyricTimeline.withLeadLines` + `LyricTimelineProvider.withLead`，`LyricTimelineProvider.java:191` 起），逐字时间不受影响。
- 间奏时除了三个点，还画出上一句（`previous`）和下一句（`next`）。

设备实测：切歌后 1.2 秒的一次截图里，卡片高亮行、面板第一行、底部胶囊三者是同一句（`_apk/unify-12s.png`）。
