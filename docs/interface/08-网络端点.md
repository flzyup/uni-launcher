# 08 网络端点与外部服务参考（Network Endpoints）

本文列出 UNI 桌面（D:\PO\uni-launcher）**全部出站请求与入站 HTTP 端口**：谁在请求、完整 URL、方法、请求头、超时、体积上限、校验方式、降级行为，附 `文件:行号`。
重点覆盖 OTA 更新链（检查 API + HTTP APK 下载 + 校验 + 安装前置）与歌词四家目录（含可用代码复现的 EAPI 签名）。
只在原生侧流转的凭证（夸克 token/cookie）不进 Flutter；本文不含任何真实 token、密钥文件或车辆数据。

## 仓库强制约定（AGENTS.md，必须复述并遵守）

- UNI 桌面的 OTA 更新检查 API 使用 `https://ota.i4o.xyz`。
- `share-ota.circleai.tech` 是 **APK 下载域名**，不是更新检查 API。当前服务签发该域名的 **HTTP** 下载链接；构建时必须保留对应的下载域名及 HTTP 白名单，下载内容仍需校验大小和 SHA-256。
- 用户未明确允许时不要推送 Git 远程。

### 2.2 检查（GET `/v1/updates/check`）

1. 参数：`package=xyz.i4o.uni.launcher`、`version_code`、`sdk`、`abis`（逗号拼接）、`channel=stable`、`platform`（`update_controller.dart:226-233`）。
2. 传输约束：`followRedirects=false`；非 200 直接抛 `HttpException('服务暂不可用')`；响应超 64 KiB 抛 `响应过大`（`:197-203`）。
3. 结构校验：`schema_version==1`、`update_available` 必须布尔（`:234-235`）。
4. 发布体校验（`update_available==true` 时）：`package_name` 必须等于本包；`version_code` 必须大于当前；`artifact.abi` 必须 `universal` 或在 `abis` 里；`0 < size_bytes <= 512 MiB`；`sha256` 必须匹配 `^[a-fA-F0-9]{64}$`（`:240-249`）。
5. 无更新时区分 `latest` 与 `incompatible`（服务端返回 `reason=="no_compatible_release"`）（`:258-263`）。

### 3.2 网易云 EAPI 信封（逐字节可复现）

输入：`songId`（long）。输出：HTTP body `params=<大写HEX>`。

1. `path = "/api/song/lyric/v1"`（注意：与请求 URL 的 `/eapi/song/lyric/v1` 不同，`path` 参与摘要的是 `/api/...` 形式）。
2. `json = {"id":<songId>,"cp":false,"tv":0,"lv":0,"rv":0,"kv":0,"yv":0,"ytv":0,"yrv":0}`（字段顺序、无空格必须一致）。
3. `digest = lowercase(hex(md5("nobody" + path + "use" + json + "md5forencrypt")))`。
4. `plain = path + "-36cd479b6b5-" + json + "-36cd479b6b5-" + digest`。
5. `key = "e82ckenh8dichen8"`（ASCII），`AES/ECB/PKCS5Padding` 加密 `plain` 的 UTF-8 字节。
6. 密文转十六进制并**转大写**，拼成 `params=<HEX>`，以 `Content-Type: application/x-www-form-urlencoded; charset=UTF-8` 发出，附带 `Cookie: os=pc; appver=2.9.7;`、`Referer/Origin: https://music.163.com/`。

依据：`LyricCatalog.java:311-328`、`330-339`（md5）、`535-537`（form 头）、`289-290`（URL/Referer/Cookie）。响应读 `code==200` 后取 `lrc`、`tlyric`、`yrc`、`yromalrc`（空则 `romalrc`）（`:291-298`）。

### 3.4 歌词的失败语义

- 请求失败/非 2xx：`exchange()` 返回空数组，不抛异常（`LyricCatalog.java:542`）。
- 响应超 256 KiB：直接返回空，绝不截断解析（`:548`）。
- 候选不足 `ACCEPT`：返回空，跳过缓存写入（`:285`、`:368`、`:418`、`:460`）。
- 无任何目录命中：`LyricTimelineProvider` 记 miss 30 分钟，避免卡住播放时反复请求（`Jint/lyrics/LyricTimelineProvider.java:35`、`115-119`、`142-151`）；内存 LRU 只留 16 首（`:34`）。
- 内存命中可直接复用序列化 JSON，不重复序列化（`:199-224`）。
- 时长 <20 s 不查（`:113`）。

## 9. 新增一个网络接口的检查清单

新增任何出站请求前逐条过一遍（照抄顺序即可）：

1. **主机归属**：写清是检查 API（`https://ota.i4o.xyz`）还是下载/内容域名；若是下载域名，同时更新 `otaHosts` 与 `otaHttpHosts` 的默认值和构建参数（`update_controller.dart:11-15`、`app/README.md:151-153`）。
2. **协议**：默认 HTTPS。要 HTTP 就把主机名放进显式白名单，并在代码里做精确匹配（参考 `isTrustedDownload`，`update_controller.dart:33-37`）；不要在别处依赖 `usesCleartextTraffic`（`Manifest:51`）。
3. **超时预算**：连接/取流/读体分别给上限，短请求 ≤10 s；总预算不得超过调用方（binder 快照、UI 帧）能容忍的时间。参照 `update_controller.dart:191-211`、`LyricCatalog.java:515-556`。
4. **体积上限**：读流时边读边计数，超限直接放弃，不做截断解析。参照 `LyricCatalog.java:548`、`OfficialWeatherAdapter.java:230`。
5. **响应校验**：状态码 + 结构版本字段 + 每个字段的类型/范围；数字要有上下界（`update_controller.dart:240-249` 是范本）。
6. **完整性**：下载类必须校验长度与 SHA-256，缺一不可（`update_controller.dart:472-477`）。
7. **落盘与缓存**：缓存键必须由内容身份决定（如 `SHA-1(key).lyric.json` + `cv` 版本字段），版本不匹配即视为无缓存（`LyricCatalog.java:98`、`113`、`123-137`）。
8. **线程**：绝不在主线程或 binder 快照路径上做网络；用单线程 executor + 代际/请求门丢弃过期响应（`LyricTimelineProvider.java:52-59`、`ForecastRequestGate.java:4-12`）。
9. **降级**：失败必须返回“空值 + 原因”，不得抛到 UI；失败态要有 TTL，避免请求风暴（`LyricTimelineProvider.java:35`、`142-151`）。
10. **凭证**：token/cookie 只留原生侧；展示层只拿派生状态（`QuarkPan.java:44-46`）。任何密钥不得进仓库（`tools/sign_car_apk.py` 头注释同规则）。
11. **清理**：新增缓存目录必须落在 `cacheDir` 或 `filesDir/<sub>`，并确认垃圾清理器的 `never` 规则不会误删（见 09 号文档）。
12. **文档**：更新本文件的端点总表、失败清单、`## 本文依据`；若新增权限，同时更新 `Manifest` 与 07 号文档的权限表。
