# 03 · 事件流与通道参考（UNI 桌面 ⇄ Android）

本文是 UNI 桌面（Flutter + Android 原生，仓库 `D:\PO\uni-launcher`）**全部 EventChannel / MethodChannel 推送方向**的接口参考，供后续 AI 智能体在排查"界面不刷新""事件收不到""重复重建"时直接查表。
用法：先在"通道总表"定位通道，再读对应小节确认**载荷是 JSON 字符串还是 map**（这是最常见的错判点，`jsonDecode` 与直接取 Map 混用会立刻抛异常），然后看"节流与去抖"确认是否被设计性地丢弃过。
所有断言后跟 `文件:行号`，行号对应本仓库当前源码；不确定处标注"待确认"，不要据本文臆造键名。
快照内部的键级结构见 `04-snapshot-schema.md`；本文只描述"包怎么来、多久来一次、谁在收"。

## 2. 桌面快照推送：`xyz.i4o.uni.launcher/events`

### 2.1 形态

- 载荷是 **JSON 字符串**：原生 `sink.success(cached)`，`cached` 是 `JSONObject.toString()`（`MainActivity.java:219`、`:314`）。
- Dart 侧在 `native_gateway.dart:33-35` 统一 `jsonDecode(value as String)` 后转成 `Map<String,dynamic>`，因此**订阅方永远拿不到裸 Map**；不要在该流上写 `value is Map` 判断。
- 同一个通道还有一次性 `snapshot` 方法（`MainActivity.java:105-110`），bootstrap 走它：`native_gateway.dart:30-31`。

### 2.2 触发时机

`publish()` 是唯一出口（`MainActivity.java:289-299`），被以下路径调用：

| 触发源 | 位置 |
|---|---|
| `LauncherRuntime` 数据源回调（媒体、车辆、系统状态、日历、信号灯、包安装等） | `LauncherRuntime.java:505-513` → 监听器 → `MainActivity.java:345` |
| `onStart` / `onResume` / `onNewIntent` / `onConfigurationChanged` | `MainActivity.java:347`、`:354`、`:495`、`:379` |
| 内容区布局变化（尺寸真的变了才发） | `MainActivity.java:198-200` |
| 命令处理完成（`action`、底栏命令） | `MainActivity.java:262-287` |
| 权限回调 | `MainActivity.java:381` |

### 2.3 节流 / 去抖（重点：这就是"为什么不刷新"的答案）

| 机制 | 值 | 位置 | 后果 |
|---|---|---|---|
| 统一发布间隔 | **80 ms**（约 12.5 包/秒上限） | `LauncherRuntime.java:33`、`:505-513` | 同一 looper turn 内的多次 `publish()` 合并成一包；突发数据源不会逐事件重建 |
| 无 sink 不构包 | `if(sink==null)return;` | `MainActivity.java:297-298` | Dart 还没订阅时**不构建**增量包，避免把分组标成"已投递"（注释 `:289-296` 解释过这个坑） |
| 时间戳签名去重 | 正则把 `*AtMs` / `*AtElapsedMs` 归一成 `"t":0` 后比较 | `MainActivity.java:304-307`、`:309-315` | 只有时间戳变化的包**不发**；空闲时 0 fps |
| 分组游标增量 | `StaticCursor.apps/design/media/settings` | `LauncherRuntime.java:71-73`、`:200-221` | 未变化的分组不出现在包里（`apps`/`savedDesign`+`appNames`/设置目录） |
| `partial` 标记 | `!(wantApps&&wantDesign&&wantMedia)` | `LauncherRuntime.java:216` | Dart 据此对上一包做合并（`launcher_controller.dart:193-213`） |
| 媒体资源指纹 | `artwork.hashCode()+":"+lyrics.hashCode()` | `LauncherRuntime.java:230-233` | 只有封面/歌词文本变了才推进 `mediaRevision`；否则 `artwork`/`lyrics` 被 `remove`（`:207`） |
| 布局指纹 | `design.hashCode()+":"+names.hashCode()` | `LauncherRuntime.java:226-229` | 布局任何内容变化都推进 `designRevision` |
| 包事件合并 | **600 ms** | `LauncherRuntime.java:598-606` | 连续安装/卸载只触发一次后台扫描 |
| 设置目录延迟预热 | **1500 ms** 后 `settingsRevision++` | `LauncherRuntime.java:144-146`、`:203`（`isWarmed` 门） | 设置目录只按游标补发一次，未预热时该键根本不出现 |
| 遥测包体积红线 | `> 65536` 字符且非静态包 → 打日志 | `MainActivity.java:222-223` | 出现该日志说明有 payload 泄进增量包，不是"卡了" |
| 应用列表后台构建 | 后台线程 + generation 丢弃过期结果 | `LauncherRuntime.java:608-622` | 首帧不阻塞；`appsRevision++` 在 `:624-628` |

### 2.4 订阅 / 退订生命周期

- `onListen`：`sink=events; sentSignature=null; publish();`（`MainActivity.java:171`）——**订阅即刻补发一包**，且因 `sentSignature=null` 一定发得出去。
- `onCancel`：`sink=null; sentSignature=null;` 并把四个游标重置为 `-1`（`MainActivity.java:172-177`）。这是**故意**的：下一个订阅者是全新的 Dart 控制器，没有缓存分组，第一包必须带全量分组。若删掉这段重置，会出现"重进桌面后应用图标空白、徽标退化成包名"（注释 `:174-176`）。
- `onDestroy`：`events.setStreamHandler(null)`（`MainActivity.java:506`），同时 `sink=null`（`:507`）。
- `onStop`：`rt.removeListener(this)`（`MainActivity.java:362`）；`onStart` 的 `addListener` 会重新拉起各数据源（`LauncherRuntime.java:485-493`），`removeListener` 在最后一个 owner 离开时停掉全部数据源（`LauncherRuntime.java:495-500`）。
- **`sink` 生命周期与 `LauncherRuntime` 监听生命周期是两件事**：即使 sink 存在，`onStop` 之后数据源已停，包不会再"自然"变新（只会在 `onStart`/`onResume` 的重放里来一次）。

### 2.5 Dart 侧订阅管理

| 位置 | 内容 |
|---|---|
| `app/lib/controller/launcher_controller.dart:95` | `StreamSubscription<Map<String, dynamic>>? _subscription;` |
| `launcher_controller.dart:165-168` | `_subscription = gateway.events.listen(_receive, onError: ...)` |
| `launcher_controller.dart:137-164` | 先 `bootstrap()` 拿首包，再订阅；`initialSettings` 用于打开设置页 |
| `launcher_controller.dart:657` | `dispose()` 里 `_subscription?.cancel()` |
| `launcher_controller.dart:188-297` | `_receive`：`partial` 合并、`_carriedKeys`/`_carriedMedia` 保留旧值、图标/缩略图缓存预算（`:98-99`、`:180-186`） |

## 3. 底栏 / 面板事件：同名 `xyz.i4o.uni.launcher/events`

- 通道注册：`GlobalDockService.java:251`；`onListen` 只做 `sink=s; sentSignature=null; publish();`（`:252-253`），`onCancel` 只清 `sink`/`sentSignature`（`:254`）。
- ⚠️ **与主窗口不同**：底栏/面板 `onCancel` **不重置游标**（对比 `MainActivity.java:176`）。同一个 `OverlayWindow` 再次 `onListen` 时，游标仍是已推进状态，可能收到 `partial` 包。实际流程里 `OverlayWindow` 每次都是新实例（`GlobalDockService.java:359-360`、`:403`），所以当前不触发；若将来复用窗口，必须补上游标重置。
- 载荷同样是 **JSON 字符串**（`GlobalDockService.java:313`、`:319`）。
- 去重同样用时间戳归一签名（`GlobalDockService.java:316-317`）。
- 面板缩略图按**数组身份**投递：`items != sentRecentItems` 才带 `recentTasks`，关闭面板时投递空数组退役旧图（`GlobalDockService.java:321-329`）；锁切换为了"立即送达"会**新建数组**（`:430-435`）。
- 载荷比主窗口多三个键：`hostMode`（`global-dock`/`global-panel`）、`globalDock`、可选 `recentTasks`（`GlobalDockService.java:343-350`）。Dart 用 `hostMode` 判断自己是不是覆盖层窗口（`launcher_controller.dart:75-76`）。
- 谁触发：`runtime.addListener(this,this::update)`（`GlobalDockService.java:212`）→ `update()` → `publish()`（`:465-474`）。
- 销毁：`close()` 里 `methods.setMethodCallHandler(null)` + `events.setStreamHandler(null)`（`GlobalDockService.java:336-341`），先 `spectrumBridge.close()`（`:337`）。

## 4. OTA 事件：`xyz.i4o.uni.launcher/ota-events`（MethodChannel）

- **它不是 EventChannel**，没有 `setStreamHandler`。注册点 `MainActivity.java:102`（`MethodChannel`）。
- 方向是**原生 → Dart 的 `invokeMethod`**：`requestBootUpdateCheck()` 里 `otaEvents.invokeMethod("boot-check", null)`（`MainActivity.java:32-35`，调用线程 `runOnUiThread`）。
- 唯一触发源：开机服务 `OtaBootService.onHandleIntent` → `MainActivity.requestBootUpdateCheck()`（`OtaBootService.java:9-11`）。
- Dart 消费：`update_controller.dart:78-83` 用 `_otaEvents.setMethodCallHandler` 收 `boot-check`，置 `_bootRequested=true`，已就绪则立即 `_startupCheck()`，否则等 `initialize()` 末尾补跑（`:107-113`）。
- 退订：`dispose()` 里 `_otaEvents.setMethodCallHandler(null)`（`update_controller.dart:537`）。
- ⚠️ 前提：`MainActivity` 必须"活着"且 `otaEvents` 非空（`MainActivity.java:33-34` 判空）。冷启动时 Dart 还没装 handler，包会丢；因此 Dart 侧用 `_bootRequested` + 30 秒兜底定时器（`update_controller.dart:112`）双保险。
- 反方向的 OTA 控制全部走 `platform` 通道：`otaInfo`/`otaDismiss`/`otaEnabled`/`otaInterval`/`otaCanInstall`/`otaInstall`（`MainActivity.java:111-131`）。

## 7. 氛围灯：`xyz.i4o.uni.launcher/ambient-light`

- **双向**：Dart 调 `status`/`enable`/`color`/`brightness`/`zone`（`AmbientLightBridge.java:78-107`）；原生用 `invokeMethod("state", stateMap)` 反推（`:63-77`，`main.post` 后调用，见 `:66-74`）。
- 返回值是 **Map**（不是 JSON 字符串）：`status()` 返回 `Map<String,Object>`（`AmbientLightWriter.java:315-353`），注释明确说明原因（`:308-314`）。
- `state` 推送键（= `status()` 全量）：`available`、`enabled`、`backend`、`reason`、`lastRgb`、`lastBrightness`、`colorWrites`、`brightnessWrites`、`enableWrites`、`resolved`、`unresolved`、`handlePresent`、`switchApplied`、`desiredEnabled`、`pendingBrightness`、`lastBrightnessStep`、`resolvedIds`、`lastWrite{op,function,zone,value,ok,error}`。
- 触发时机：任何写操作后状态变化（`AmbientLightWriter.java:768-769` 广播给全部 `StateListener`）。
- 节流：写入最小间隔 **50 ms**（`AmbientLightWriter.java:78`、`:489`）；Dart 侧渲染时钟 16 ms、对外发布 50 ms、状态轮询 5 s 兜底（`app/lib/platform/ambient_light.dart:72`、`:85`、`:100`、`:40`）。
- Dart 消费：`handleNativeCall` 只认 `call.method == 'state'`（`ambient_light.dart:422-428`）→ `applyNativeState`（`:402-419`）。
- 退订：`AmbientLightBridge.close()` 移除监听 + `channel.setMethodCallHandler(null)`（`AmbientLightBridge.java:158-162`）；Dart 侧 `setMethodCallHandler` 在构造时设置（`ambient_light.dart:139`）。
- ⚠️ 全进程只有一个 `AmbientLightWriter`（`AmbientLightBridge.java:43`、`:51-60`），但**每个引擎都有一条 `ambient-light` 通道**；所以"两个引擎都收到 state"是正常的，不要据此判断重复初始化。

void setDemand(Object owner, bool enabled) {
  final wasActive = _owners.isNotEmpty;
  if (enabled) { _owners.add(owner); } else { _owners.remove(owner); }
  final active = _owners.isNotEmpty;
  if (wasActive == active) return;
  if (active) {

  }
}

## 11. 排查清单：为什么不刷新

1. **看 `sink` 是否为空**：主窗口 `publish()` 在 `sink==null` 时直接返回（`MainActivity.java:297-298`），Dart 未订阅 → 永远没包。
2. **看是否被签名去重吞掉**：只有 `*AtMs`/`*AtElapsedMs` 变化的包不发（`MainActivity.java:304-307`）。若新增字段命名成 `xxxAtMs`，它**不会**让包变新。
3. **看分组游标**：`apps`/`savedDesign`/`appNames`/`systemSettings` 只在 revision 推进时出现；其余包是 `partial`（`LauncherRuntime.java:200-221`、`:216`），Dart 侧合并逻辑在 `launcher_controller.dart:193-219`。
4. **看数据源是否在跑**：`removeListener` 在最后一个 owner 离开时会停掉媒体/车辆/天气/状态/日历/信号灯（`LauncherRuntime.java:495-500`）。
5. **看可见性退避**：不可见时车辆 3 s、系统状态 5 s（`OfficialCarReader.java:116`、`SystemStatusAdapter.java:49`）。
6. **看 TTL**：信号灯 5 s 自动过期（`AmapTrafficLightAdapter.java:18`、`:88`）。
7. **看媒体资源指纹**：封面/歌词没变时 `artwork`/`lyrics` 会从包里被删掉（`LauncherRuntime.java:207`、`:230-233`），Dart 靠缓存合并（`launcher_controller.dart:202-212`）。
8. **不要把 `ambient-light`/`spectrum`/`map/<id>` 当快照流**：它们是独立的高频流，改这些不应该重建整棵界面树（`SpectrumBridge.java:22-24` 的设计说明、`audio_spectrum.dart:7-8`）。
