# 07 原厂车控通道（OEM Car Channels）接口参考

本文用于给后续 AI 智能体提供 UNI 桌面（D:\PO\uni-launcher）**原厂车控/车辆状态**通道的逐项事实：谁能调、怎么调、失败长什么样、在哪一行。
覆盖空调、座椅、风向、温度、drive-mode/启停、车辆状态读取、氛围灯，以及“无车机时会看到什么”。
所有 `文件:行号` 以仓库当前代码为准；`docs/OFFICIAL_CAR_API.md` 只作对照，凡与代码不一致处在第 9 节单列。
本文不修改任何源码，也不含任何车辆日志、APK 内容或密钥。

## 1. 前置：这是原厂私有 SDK，签名权限才可见

| 事实 | 依据 |
| --- | --- |
| 通道入口是 `com.ecarx.xui.adaptapi.car.Car.create(Context)`，实现来自车机自带的 `ecarx.adapterapi.jar`，本仓库**不打包、不静态链接**，全部走反射 | `OfficialCarContract.java:43`、`OfficialCarReader.java:445` |
| 读写厂商属性需要 `android.car.permission.CAR_VENDOR_EXTENSION`（`signature|privileged`） | `OfficialCarContract.java:42`、`Manifest:18` |
| 运行时唯一权限闸门：`context.checkSelfPermission(PERMISSION) == PERMISSION_GRANTED` | `OfficialCarReader.java:399-401` |
| 该权限只有与车机原厂 Launcher 同证书签名的包才拿得到；开发/模拟器包是另一张证书，装到实车上拿不到 | `docs/OFFICIAL_CAR_API.md:29`、`tools/sign_car_apk.py`（用 `platform.pk8/platform.x509.pem` 另签） |
| 另一个原厂权限 `ecarx.oem.permission.OPENAPI_MEDIACENTER_PERMISSION` 只被媒体桥使用，与车控无关 | `Manifest:20`、`Jint/OfficialMediaBridge.java:111` |
| `ecarx.oem.permission.USER` 只在清单里声明，代码里没有对应 `checkSelfPermission` | `Manifest:19`（全仓无引用） |

**缺权/缺车的降级行为（统一语义：不崩，只是“不可用”）**

1. `initializeOnMain()` 先查权限，不通过就 `publishUnavailable("车辆厂商读取权限未授权")` 并直接返回，**不会**尝试 `Car.create`（`OfficialCarReader.java:419-421`）。
2. 每轮采集开始再查一次权限；中途被撤销同样只改成不可用快照（`OfficialCarReader.java:489`）。
3. `command()` 的任何一次调用都会重新过权限、连接、写签名三道闸，任一不满足**返回 false**，不抛异常给 Flutter（`OfficialCarReader.java:133-137`）。
4. 上层 `LauncherRuntime` 把 false 翻成 toast，界面不阻断：空调 “尚未连接空调，可从空调面板打开原车应用”（`J/LauncherRuntime.java:456-460`）、设置 “车辆未连接或未确认该设置值”（`J/LauncherRuntime.java:452-455`）、记忆配置 “车辆未连接或不支持该驾驶模式”（`J/LauncherRuntime.java:337-344`）。
5. 快照结构仍在：`connected=false`、`writable=false`、`readOnly=true`、`fields/climate/seatCapabilities` 为空对象、`reason` 写原因（`OfficialCarReader.java:1041-1052`）。

补充事实：

- action 归属判定在 `J/core/CommandPolicy.java:7-19`（`isClimateAction` / `isSeatAction` / `isSettingAction`），`OfficialCarCommand.isSetting` 再判一次（`OfficialCarCommand.java:20-22`）。
- `OfficialCarCommand.key()` 是 action→字段键的唯一映射（`OfficialCarCommand.java:44-57`），键不存在即整条命令作废（`command()` 返回 false）。
- 温度硬门槛：只有 `min==16 && max==31 && step==0.5` 且当前值在区间内才允许写（`OfficialCarCommand.java:63-71`）；`TEMP_MIN/MAX/STEP` 在写前现读（`OfficialCarReader.java:790-793`）。
- 温度解码只接受 16..31、0.5 步进，`format=1` 时先 `(raw-32)*5/9`（`OfficialCarReader.java:972-981`）。
- 风量 8 = AUTO 模式，**不作为第 9 档写入**；写前若 `automatic=true` 则该项 `writable=false`（`OfficialCarReader.java:736-739`、`992-997`；`OfficialCarCommand.java:72-79`）。
- 座椅档位只接受 `'0'..'3'` 单字符，`driverZone` 必须是 1 或 4，否则 plan 为 null（`OfficialCarCommand.java:80-87`）。
- `climate-power` 从“开”变“关”时会先抓一份配置快照（`OfficialCarReader.java:144-145`），再次开机后按 240 ms 间隔逐项恢复（`OfficialCarReader.java:841-859`），AUTO 态不恢复风量（`:847-848`）。
- drive-mode 的 selection 值：ECO `0x22010101`、COMFORT `0x22010102`、DYNAMIC `0x22010103`、XC `0x22010104`、HDC `0x22010105`、PURE `0x22010106`、HYBRID `0x22010107`、POWER `0x22010108`、ECO_HEV_PHEV `0x22010110`、COMFORT_HEV `0x22010111`、RACE `0x22010115`（=SPORT_PLUS）、INDIVIDUAL `0x22010140`（=CUSTOM）；`SPORT_PLUS`/`CUSTOM` 输入被折叠，故不接受（`OfficialCarContract.java:124-135`、`147-179`；`OfficialCarCommand.java:26-35`）。
- 命令单槽：一次只允许一个待确认命令，`commandBusy` CAS 失败即返回 false（`OfficialCarReader.java:147-148`）；排队超过 2000 ms 作废（`:902-906`）；5 秒无读回记 `timeout`（`:917`、`:950-964`）；断线不重放（`:908-911`）。

## 8. 在模拟器 / 无车机上会发生什么（开发环境判断）

1. **`ecarx.adapterapi` 类不存在**：`Class.forName("com.ecarx.xui.adaptapi.car.Car")` 抛 `ClassNotFoundException` → `setupError` 被写成 `ClassNotFoundException:...`，快照 `reason="官方车辆接口初始化失败：ClassNotFoundException..."`，`connected=false`（`OfficialCarReader.java:436-439`）。
2. **没有 `CAR_VENDOR_EXTENSION`**：更早一步就返回 `reason="车辆厂商读取权限未授权"`，连 `Class.forName` 都不会执行（`:419-421`）。
3. **轮询仍在跑**：每 1 s（可见）/3 s（不可见）重新走一遍，`publishedAtElapsed` 持续刷新，所以界面拿到的是“初始化失败”而不是“读取超时”（`:111-118`、`:486-494`）。只有工作线程真的卡死/被关闭超过 5 s，才会看到 `reason="车辆读取已超时，等待服务恢复"`（`:124-125`）。
4. **标准 `android.car.Car` 在模拟器上存在但 `getCarManager("property")` 可能返回 null** → `setupError="PROPERTY_MANAGER_ABSENT"`（`:407-409`）。
5. **演示模式自动打开**：`Build.FINGERPRINT` 含 `generic` 或 `MODEL` 含 `sdk_gphone`/`Android SDK` 时首启自动写 `demo=true`（`J/LauncherRuntime.java:107`）。此时：
   - 空调 action 走本地 `ClimateState` 模拟器，完全不碰车辆（`J/LauncherRuntime.java:456-460`；`J/core/ClimateState.java:4-38`）；
   - `climate` 快照来自模拟器，初始 `left=right=22.5, fan=3, power/auto/ac=true, sync/recirc=false`（`J/LauncherRuntime.java:167-171`、`ClimateState.java:5-8`）；
   - 记忆配置**不发起车辆写入**：“演示模式不写入车辆设置”（`J/LauncherRuntime.java:335`、`:453`；`OfficialCarReader.java:268`）。
6. **氛围灯**：`borrowedFunctions()` 恒为 null → 每次写入 `available=false, reason="车机车辆服务尚未就绪"`，`status()` 里 `backend="未接入"`、`handlePresent=false`、`unresolved` 列出全部解析不到的名字（`AmbientLightWriter.java:315-353`）。
7. **原车相机入口**：`cameraCapability()` 恒 `-1` → toast “当前车辆未提供原车全景入口”（`J/LauncherRuntime.java:443-449`、`Jint/AppRepository.java:238`）。
8. **红绿灯**：模拟器上没有导航广播，`available=false, reason="waiting"`，5 s 后变 `expired`（`Jint/AmapTrafficLightAdapter.java:50-53`、`91-100`）。
