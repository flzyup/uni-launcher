# 04 · 快照 schema（`snapshot` 返回的 JSON）

本文逐键说明 UNI 桌面 `xyz.i4o.uni.launcher/platform` 通道上 **`snapshot` 方法返回的 JSON 字符串**，供后续 AI 智能体在解析、新增字段或排查"字段没有值"时查表。
用法：先在 §2 找顶层键，再按 §3 进入子对象，媒体看 §4，歌词时间轴看 §5。
重要前提：`snapshot` 是 **字符串**（`MainActivity.java:106`、`native_gateway.dart:30-31` 的 `jsonDecode`），且**默认是增量包**——`partial=true` 时大部分静态载荷**不在包里**（`LauncherRuntime.java:216`），合并规则在 `launcher_controller.dart:193-219`。
键名严格照源码抄写；写"待确认"的条目是真的没在代码里找到，不要补全。

---

## 1. 调用形态与两种宿主

| 宿主 | 方法 | 返回 | 位置 |
|---|---|---|---|
| 主窗口 | `snapshot` | `cached`（JSON 字符串，含设置目录） | `MainActivity.java:105-110`、`:209-224` |
| 底栏 / 面板 | `snapshot` | `packet().toString()`（JSON 字符串，含 `hostMode`/`globalDock`） | `GlobalDockService.java:239`、`:321-329`、`:343-350` |
| 诊断 | `dumpsys --uni-state` | `UNI_STATE=` + 裁剪后的 JSON（**不是** Dart 接口） | `MainActivity.java:317-335` |

- 主窗口快照走 `snapshotWithSettings(cursor)`（`LauncherRuntime.java:157`、`:213`），底栏/面板走 `snapshot(cursor)`（`:154`、`GlobalDockService.java:344`）。两者差异**只有** `systemSettings` 是否参与（`LauncherRuntime.java:203`）。
- 快照包由 `buildSnapshot` 组装（`LauncherRuntime.java:165-223`），之后 `MainActivity.decorate()` 追加窗口相关键（`:233-259`）。

## 3. 顶层子对象

### 3.1 `systemStatus`（`SystemStatusAdapter.java:69`，值由 2 s/5 s 轮询组装 `:34-50`）

> 该对象是"上次轮询结果的原样回放"，构造时初值是 `"{}"`（`:21`）。因此**首帧可能出现空对象**——`{}` 不等于"设备没有蓝牙"，只等于"还没轮到第一次 poll"。每个子对象内部再按能力做缺键。

| 键 | 类型 | 含义 | 何时缺省 | 位置 |
|---|---|---|---|---|
| `bluetooth` | object | `{known, enabled, audio, phone, connected}` | 异常时 `known=false`+`reason` | `:70-77` |
| `network` | object | `{wifiKnown, wifi, wifiLevel, hotspot, clientsCallbackRegistered?, clients?, mobileKnown, mobileEnabled, mobileLevel, mobileType, mobileLabel}` | 部分键按能力出现 | `:78-96` |
| `usb` | object | `{known, count, visible}` | 同上 | `:102-108` |
| `charging` | object | `{known, mode, status, visible, error}`（无线充电） | 同上 | `:109-115` |
| `dvr` | object | `{known, visible, mode?, recording?}` | 未配置 DVR 时只有 `known`/`visible` | `:116-123` |
| `messages` | object | `{known, count}`（未读通知数） | 无该 provider 时是空对象 | `:124-130` |
| `account` | object | `{known, loggedIn, source, name?, avatarUrl?, memberLevel?, memberLevelName?, reason?, apiVersion?, implementation?}` | 未就绪时 `known=false` | `:131-173` |
| `memory` | object | `{totalBytes, usedBytes}` | 读取失败时缺省 | `:42-46` |

- `wifiLevel`：`0..4`，未连接为 **-1**（`:85`）。
- `mobileLevel`：信号等级，未知为 **-1**（`:23`、`:92`）；`mobileLabel` 是 `2G/3G/4G/5G/""`（`:97-101`）。
- 哨兵：任何子对象读取失败都会变成 `{known:false, reason:<异常类名>}`（`:174-176`）。

### 4.2 单位与哨兵速查

- **所有 `*Ms` 都是毫秒**：`durationMs`、`positionMs`、`sampledAtMs`（`MediaAdapter.java:373`、`:417-418`）。派生播放位置用 `positionMs + (now - sampledAtMs) * speed`，Dart 实现在 `app/lib/model/lyrics.dart:58-77`（`MediaTimeline.at`，并把结果夹到 `[0, durationMs]`）。
- **`speed` 缺省是 `0` 而不是 `1`**（`MediaAdapter.java:419`）：没有 `PlaybackState` 时用它外推位置会得到"卡住不动"，这是刻意的；演示模式给的是 `1`（`LauncherRuntime.java:240`）。Dart 侧 `MediaTimeline.fromJson` 的缺省是 `1`（`lyrics.dart:66`），所以"键缺失"和"键为 0"语义不同。
- **`-1 不表示未知的键这里没有**：`media` 里没有 `-1` 哨兵；`positionKnown=false` 才是"位置不可信"的表示（`:417`）。`-1` 哨兵出现在别处：`navigation` 的 `recentsDisplayId`（恒 `-1`，`GlobalDockService.java:73`）、`fields` 的 `cameraCapability=-1`（`OfficialCarReader.java:1061`）、`driverZone=0`。
- **空串语义**：`title/artist/collection/artwork/lyrics/lyricsSource/reason` 的 `""` 都表示"没有"，不是"未知但仍可用"；`thumbnails`/`artwork` 被移出增量包时 Dart 必须沿用旧值（`launcher_controller.dart:186`、`:202-212`）。
- **封面是 data URI**：`data:image/jpeg;base64,`，Dart 解码前会剥掉 `,` 前缀（`launcher_controller.dart:708`），并受 `256 条 / 4 MB` 预算限制（`:98`）。

## 5. `lyricTimeline` v1 格式

### 5.1 产地与消费地

- Java 生成：`LyricTimeline.toJson()`（`app/.../integration/lyrics/LyricTimeline.java:640-672`），**每个曲目序列化一次**后缓存在内存/磁盘（`LyricTimelineProvider.java:199-224`）。
- 传输形态：**一个 JSON 字符串**塞进 `media['lyricTimeline']`（`MediaAdapter.java:420`）。
- Dart 解析：`LyricTimeline.parse`，位置 `app/lib/model/lyric_timeline.dart:183-225`。

### 5.2 结构

```json
{"v":1,"lines":[{"t":1000,"d":2000,"x":"你好世界","tr":"第一行","ro":"ni hao","w":[[1000,500,"你"],[1500,500,"好"]]}]}
```

| 路径 | 类型 | 含义 | 单位 | 缺省 | 位置 |
|---|---|---|---|---|---|
| `v` | int | 格式版本，当前恒 `1` | — | 恒在 | `LyricTimeline.java:668` |
| `lines` | array | 行数组（最多 4000 行被 Dart 接收） | — | 恒在 | `:668`、`lyric_timeline.dart:169`、`:197` |
| `lines[i].t` | long | 行起始 | **毫秒** | 恒在 | `LyricTimeline.java:646`、`lyric_timeline.dart:214` |
| `lines[i].d` | long | 行时长；`0` 表示未知 | **毫秒** | 恒在（可为 0） | `:647`、`lyric_timeline.dart:215` |
| `lines[i].x` | string | 正文 | — | 恒在（可为空串） | `:648`、`lyric_timeline.dart:199` |
| `lines[i].tr` | string | 翻译 | — | **空串时整键省略** | `:649`、`lyric_timeline.dart:217` |
| `lines[i].ro` | string | 罗马音 | — | **空串时整键省略** | `:650`、`lyric_timeline.dart:218` |
| `lines[i].w` | array | 逐字：`[start, duration, text]`（**数组不是对象**） | 毫秒 | 仅当该行有逐字时间才出现 | `:651-661`、`lyric_timeline.dart:202-211` |

Dart 解析的兜底与裁剪：载荷不是 `String`／为空／超 **2,000,000** 字符 → 空时间轴（`:184-185`）；`lines` 不是数组 → 空（`:194-195`）；单行 `x` 与 `w` 都空 → 丢弃（`:212`）；文本按 **4096** 字符右截断（`:170`、`:375-381`）；解析后按 `t` 升序排序（`:223`）。

### 5.3 语义约定（写渲染代码必看）

| 值 | 含义 | 位置 |
|---|---|---|
| `d = 0` | 行时长未知 → 用下一行起点推算，最后一行取 `holdMs = 5000` | `lyric_timeline.dart:302-308`、`:43` |
| 行间隙 ≥ `minInterludeMs = 5000` | 视为间奏，`LyricCursor.interlude = true`，不显示任何行只显示标记 | `:168`、`:251-275` |
| `lineStartMs = -1` / `elapsedMs = -1` | 当前没有活动行 | `:107-113`、`:318-323` |
| `wordProgressPermille` | 0..1000 的整千分比（不是 0..1 浮点） | `:322`、`:149-153` |
| `trailingWord = true` | 该字跑到行尾，填充不得停在这个字上 | `:331-339` |
| `sungPrefix` | 只有逐字时间才给高亮前缀；纯 LRC 返回 `''`，可选 `estimatedSungPrefix` 才按比例估算 | `:118-132` |
| `hasTranslation` / `hasWordTiming` / `qualityScore()` | 质量判据（逐字 4 分、翻译 2 分、罗马音 2 分） | `:179-180`、`:383-390` |

## 8. 解析注意事项

1. **先判 `partial`**：为 `true` 时必须与上一包合并，否则 `apps`/`savedDesign`/`appNames`/`artwork`/`lyrics`/`systemSettings` 会凭空消失（`launcher_controller.dart:193-219`）。
2. **`savedDesign` 是字符串**，需要二次 `jsonDecode`（`launcher_controller.dart:139-146`）；`appNames` 可能在顶层也可能是 `savedDesign` 内（`LauncherRuntime.java:632-641` 的迁移逻辑）。
3. **`systemStatus`/`weather`/`calendar` 是"最后一次轮询的原文回放"**（`SystemStatusAdapter.java:69`、`OfficialWeatherAdapter.java:238`、`SystemCalendarAdapter.java:49`），所以它们的 `updatedAt` 类字段可能很旧，不代表包是旧的。
4. **`vehicle` 有 5 秒超时自毁**：读数超过 5 s 未更新会整体退回 `unavailable(...)`（`OfficialCarReader.java:124-125`），此时 `fields`/`climate` 为空对象而 `reason` 有中文说明——不要把它当"车辆不支持"。
5. **不要用 `version` 做协议判断**；需要契约版本时看 `lyricTimeline.v` 或布局文档的 `version`（§6）。
6. **`media.speed` 的 0 与缺省 1 不等价**（§4.2）。
