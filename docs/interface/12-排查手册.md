# 12 · 排障手册（UNI 桌面）

本文是「车上出问题，5 分钟内定位到哪一层」的查表手册：第 1 节是取证命令，第 2 节是日志 TAG 速查，第 3 节是「症状 → 原因 → 验证 → 修复位置」大表。
读者是后续 AI 智能体：先按第 3 节找到症状行，照着「验证方法」那列敲命令，拿到证据再改代码；不要跳过验证直接猜。
所有 `文件:行号` 对应仓库 `D:\PO\uni-launcher` 当前源码；原生路径省略前缀 `app/android/app/src/main/java/xyz/i4o/uni/launcher/`（下文写作 `…/`）。
标了「实测」的命令是本机真的跑过的（模拟器 `emulator-5554`、车机 `192.168.22.26:5555`），标 `待确认` 的没跑通或没条件跑。
命令全部 Windows PowerShell 写法，先设两个变量省事：

```powershell
$adb = 'D:\platform-tools\adb.exe'
$s   = '192.168.22.197:5555'   # 车机默认序列号，见 tools/car-verify.ps1:12；模拟器用 emulator-5554
& $adb connect $s
```

## 1. 取证命令表

| 目的 | 命令 | 说明 / 坑 |
|---|---|---|
| 装或覆盖安装 | `& $adb -s $s install -r -g .\dist\UNI-Launcher-<版本>-IP753.apk` | `-g` 顺带授予运行时权限；模拟器上系统安装器 UI 会崩（`tools/dev-local.ps1:43`），所以脚本走 `pm install -r -g`（`:44-47`） |
| 版本 / 签名 | `& $adb -s $s shell dumpsys package xyz.i4o.uni.launcher \| Select-String 'versionName\|versionCode\|signatures'` | 实测：车机返回 `versionCode=54`、`versionName=0.7.6`。**看不到 `signatures` 行说明命令被裁剪，换 `pm dump`**（`待确认`） |
| 权限到底给没给 | `& $adb -s $s shell dumpsys package xyz.i4o.uni.launcher \| Select-String 'granted=true'` | 实测：车机 37 条 `granted=true`；`android.car.permission.CAR_VENDOR_EXTENSION` **不在其中** → 车控必废（见 10 号文档第 5 节） |
| 单条特权权限 | `& $adb -s $s shell dumpsys package xyz.i4o.uni.launcher \| Select-String 'CAR_VENDOR_EXTENSION: granted=true'` | 一行就够判断签名对不对 |
| 悬浮窗 / 录音 AppOps | `& $adb -s $s shell appops get xyz.i4o.uni.launcher SYSTEM_ALERT_WINDOW`；`… RECORD_AUDIO` | 实测可用。`default` 代表用户没明确选择（前台可能仍允许），`deny` 就是真被拒 |
| **全量运行状态** | `& $adb -s $s shell "dumpsys activity xyz.i4o.uni.launcher/.MainActivity --uni-state"` | 实测可用，输出 `UNI_STATE={…}`；抛异常时输出 `UNI_STATE_UNAVAILABLE`（`MainActivity.java:332`）。它走全量快照（`:227-231`），不受增量游标影响 |
| 底栏/面板状态 | `& $adb -s $s shell "dumpsys activity service xyz.i4o.uni.launcher/.GlobalDockService"` | 输出 `UNI_GLOBAL_DOCK={…}`（`GlobalDockService.java:532-535`）。**实测：服务未运行时返回 `No services match`**，所以先确认下面那条 |
| 服务是否在跑 | `& $adb -s $s shell "dumpsys activity services" \| Select-String 'GlobalDock\|ClusterLyrics\|MediaAccess'` | 实测：车机上 `xyz.i4o.uni.launcher` 进程在（`ps -A`），但 `GlobalDockService` 没跑 |
| 屏幕枚举 | `& $adb -s $s shell "dumpsys window displays"` | 实测可用；看 `Display: mDisplayId=` 与 `init=WxH dpi`，副屏问题第一步 |
| 媒体会话 | `& $adb -s $s shell "dumpsys media_session"` | 实测可用；看 `sessions listeners` 与各 session 的 `state=PlaybackState{...}`、`metadata` |
| 共享偏好 | release 包：**`run-as` 不可用**（实测 `run-as: package not debuggable`）；shell 直接读 `/data/data/...` 是 `Permission denied`（实测） | 三个替代：① 用 `--uni-state` 里的派生字段；② 装 debug 包后 `run-as xyz.i4o.uni.launcher cat shared_prefs/launcher.xml`；③ `adb root` 后 `cat`（`待确认`：车机 ROM 是否允许 `adb root`） |
| 手动触发一次快照 | ① 切到别的应用再回桌面（`onStart`/`onResume` 都 `publish`，`MainActivity.java:347`、`:354`）② `& $adb -s $s shell am start -n xyz.i4o.uni.launcher/.MainActivity`（走 `onNewIntent` → `publish`，`:492-496`）③ 旋转/改配置（`:379`） | **内容没变不会重发**：时间戳被正则归一后签名相同就丢弃（`MainActivity.java:304-315`）。想证明「界面该刷新了」必须改一个真实值 |
| 冷启动分段耗时 | `& $adb -s $s shell am start -W -n xyz.i4o.uni.launcher/.MainActivity` + `& $adb -s $s logcat -d -s UNI-Startup` | 日志格式 `host total=<ms> onCreate=… runtime=… window=… firstDraw=…`（`StartupTrace.java:32-34`），全部相对进程启动 |
| 杀进程重来 | `& $adb -s $s shell am force-stop xyz.i4o.uni.launcher` | 会让底栏/面板一起消失，`GlobalDockService` 需要下次 `onResume` 再拉起（`MainActivity.java:354`） |
| 抓日志 | `& $adb -s $s logcat -c`；`& $adb -s $s logcat -d -s UniDock -s UniHome -s UNI-Startup`；`& $adb -s $s logcat -d \| Select-String 'flutter'` | Dart 侧 `debugPrint` 落在 `flutter` TAG（例：氛围灯帧日志，`app/lib/platform/ambient_light.dart:1217-1223`） |
| 无线 adb 端口 | `& $adb -s $s shell getprop service.adb.tcp.port` | 实测返回 `5555`；同一个属性由 `DebugBridge.writeNetwork` 写入（`DebugBridge.java:70-76`）+ `ctl.restart adbd`（`:81`） |
| 截图留证 | `& $adb -s $s exec-out screencap -p > .\artifacts\car-<时间>.png` | `tools/dev-local.ps1:60-65` 就是这么干的 |

> `--uni-state` 输出是一行几万字符的 JSON。别直接盯屏幕：`| Out-File $env:TEMP\uni.json`，再 `Get-Content … | ConvertFrom-Json` 取字段，或用 `Select-String '"vehicle":'` 定位。

## 3. 症状 → 可能原因 → 验证方法 → 修复位置

按「先查证据、再改代码」的顺序读。每一行都给到具体字段或行号，不要凭现象猜。

### 3.1 桌面不刷新（数据变了，界面不动）

| 可能原因 | 验证方法 | 修复位置 |
|---|---|---|
| 没有 sink，原生根本没构包 | 确认 Dart 已订阅：`--uni-state` 里 `media`/`design` 有值，但界面还是旧值 → 看 `MainActivity.java:297` 的早退分支 | 端到端重进一次首页；检查 Dart 是否在 `bootstrap()` 之后才 `events.listen`（`app/lib/controller/launcher_controller.dart:137-168`） |
| 增量合并丢了字段 | 第二包之后字段消失 → 检查该键是否登记在 `_carriedKeys`（`launcher_controller.dart:180`）/`_carriedMedia`（`:186`） | 在 `_receive`（`:188-297`）补登记 |
| 内容没变被签名去重 | 日志没有新包、`UNI_STATE` 值也没变 | 正常行为（`MainActivity.java:304-315`）；要刷新必须真的改一个值 |
| 数据源已停（onStop 后） | `--uni-state` 值停在最后一次 | `MainActivity.java:357-366` 的 `removeListener`；回前台 `:345` 重新挂 |
| 80 ms 合并把突发吞了 | 只看到「最终值」，没有中间过程 | 设计如此（`LauncherRuntime.java:505-524`） |

## 4. 三分法：先分清是哪一类问题

1. **是权限/签名，还是代码？**
   先跑两条：`dumpsys package … | Select-String 'granted=true'` 和 `dumpsys activity … --uni-state`。
   `granted` 里缺 `CAR_VENDOR_EXTENSION` → 签名问题，不要改代码。`--uni-state` 里字段齐全但界面不对 → 代码问题。
2. **是数据没来，还是界面没画？**
   数据没来：`--uni-state` 里该字段为空/`reason` 有值。
   界面没画：字段有值但界面旧 → 走 3.1（sink / 游标 / 去重 / `_carriedKeys`）。
3. **是哪个引擎？**
   看 `globalDock.liveFlutterEngines`（`GlobalDockService.java:67`）与 `panelEngineIdentity`（`:70`）。
   面板 identity 每次重建都会变；某个方法「在主窗口好、面板里不行」→ 十有八九是面板引擎没实现（10 号文档 3.3）。
