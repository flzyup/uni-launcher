# 空调与座椅设计方案

本方案用于评审，不连接车辆，也没有修改现有 Flutter 界面和控制逻辑。截图为 1920×1080 深蓝玻璃示例，底栏贴底高度 96 px。

- [静态预览](climate-redesign-preview.png)
- [座椅图标侧置对比](climate-redesign-seat-icons-side.png)
- [全局条音乐进度动效设计](../music-motion/README.md)
- [可交互设计原型](index.html)：温度、风量、模式、座椅档位和底栏切换仅修改示意数据。

## 底栏

保持现有顺序：A/C、主驾温度、风量、内外循环、副驾温度、电源。A/C、循环与电源直接切换；温度或风量区域打开空调弹窗。风量为 AUTO 或手动档位，状态未知时显示 `—`，颜色、图标和语义标签共同表达状态。各按钮独立响应，不随弹窗出现而改变底栏位置。

保留既有深蓝玻璃四角标识和主题色、直角/圆角配置；不新增实时背景模糊。适配浅色主题和用户主题色时，以主题样式确定文字、边框及选中态，不仅依赖颜色区分状态。

弹窗内的温度块、风量块和座椅卡片属于次级卡片，同样使用四角高亮边框；模式按钮和座椅档位保持控件级弱边框，避免所有元素都变成重框而降低层级。

## 空调图标规范

统一使用无填充、圆头圆角的线性图标，底栏和弹窗复用同一图形；尺寸较小时按像素密度微调笔画以保持清晰。图标随状态及深浅主题取色，同时提供可访问名称与不可用、未知状态。

| 功能 | 表达方式 |
| --- | --- |
| 内循环 | 带前后轮的领克 05 侧面简化轮廓，车内弯曲箭头；底栏和弹窗使用同一图标 |
| 外循环 | 相同车辆轮廓和前后轮，车外斜向箭头进入车内；与内循环的箭头形状明显区分 |
| 循环未知 | 仅轮廓或问号，语义为状态未知；不将未知表示为外循环 |
| 风量 | 复用现有风扇线性图标；AUTO 或手动档位作为文字随同展示 |
| 座椅 | 加热使用座椅与热流线图标；通风使用同一座椅轮廓及放大的风扇图标。图标放在主驾、副驾卡片标题行，使用冷暖色表达功能，当前模式加亮 |
| 电源 | 复用现有电源线性图标；颜色和选中状态跟随原车读回 |
| AUTO / A/C / SYNC | 使用标准缩写，弹窗可补充中文说明 |
| 前后除霜、风向 | 实车能力和命令尚未核对，暂不添加操作；若将来支持，分别使用标准前挡、后挡与人体风向图形，并保持同一笔画体系 |

先前提供的 05 多视图中的侧视图在当前工作区未找到原始文件；原型依据会话中的侧视参考及其溜背侧影做小尺寸轮廓简化，并非对原图线条的精确描摹。两个方向使用完全相同的底层车辆轮廓；48–52 px 小图优先保持箭头辨识。可在原型中点击循环按钮比较两态，也可直接打开[外循环预览](climate-redesign-outer.png)。

图形语义参考 [Hyundai 车主手册的内外循环说明](https://ownersmanual.hyundai.com/full_webhelp/NX4/2025/en_GN/idfc48d2f1bf8.html)和[汽车循环图标示例](https://icons8.com/icon/wzyrtXP2XpXD/air-recirculation)：车内回转代表内循环，车外箭头进入代表外循环。本原型自行绘制，没有引入第三方图标文件；具体轮廓按桌面视觉简化。

## 空调弹窗

温度和风量并排展示，直接提供加减；第二行按 A/C、AUTO、内外循环、SYNC、电源排列；底部为座椅舒适。空调窗口内电源是新增入口，需要与底栏读取同一状态并遵循相同权限、发送和读回规则。通风方向、除霜等原车能力若未核对，不添加看似可操作的按钮，保留打开原车空调入口。

弹窗与底栏维持 1920×1080 下的实际可用区域：弹窗底边不覆盖 96 px 底栏；窄窗口、放大字体或系统键盘出现时允许内部滚动。实际实现采用共享尺寸系统，按屏幕缩放布局而非固定物理像素。

## 座椅

主驾加热与通风用一条档位带表达互斥，顺序为「通风 3 / 2 / 1 / 关 / 加热 1 / 2 / 3」；档位使用独立按钮并七等分，「关」与每个数字档位同宽。主驾与副驾均使用同一等分规则，副驾为「关 / 加热 1 / 2 / 3」四等分。图标放在卡片标题行且不附加通风、加热文字：主驾通风图标紧跟「主驾」，主驾加热图标靠右，副驾加热图标同样靠右；当前模式加亮，主驾右上角不重复显示档位文字。对比方案保留档位两侧图标（原型 URL 添加 `?seatIcons=side`）。通风使用冷蓝、加热使用暖橙，选中档位加亮；副驾关闭时右上角不重复显示文字。两种图标共用同一座椅轮廓和标题行垂直中心。点击目标档位直接申请该模式和档位，按原车读回更新选中按钮；副驾开启时在顶部显示档位。控件使用明确的图标与可访问名称；无对应能力、无有效读数或车辆命令待确认时保持禁用或待确认提示，不把未知状态画成关闭。

现有演示状态 `ClimateState` 会在启用一种主驾模式时清除另一种，但 `OfficialCarReader` 目前按所选控制项发送单个原车命令，未在代码中证明实车一定会自动关闭另一项。实施前需实车对照原车行为及回读；若原车未保证互斥，必须设计串行关闭、确认读回、再切换的流程与失败处理，不能仅凭界面切换假定成功。若同时读到两项开启，应保留真实数据并提示状态待核对，不自行隐藏其中一项。

## 验证范围

设计评审包括 1920×1080 底栏贴底、弹窗区域不遮挡底栏、模式及座椅交互可在预览中切换；示意交互不代表 Android 原生适配或真实车辆控制已验证。后续实施需补充不同权限/不可读/待确认状态、主题色和字体放大、模拟器及停车状态下实车读回验证。
